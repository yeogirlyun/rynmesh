## 浏览器与真实 HTTP 业务闭环

使用生产构建、Ryn 完整节点、确定性本机 OpenAI 兼容 HTTP 模型。通过页面验证能力并选择默认模型；启用前后分享保持独立。

1. `ryn_list_models` 读取实际来源。
2. 模型提出分享 `acceptance-model`，页面展示对象、个人空间范围及前后变化。
3. 重启节点，原待确认审批保留，未自动执行。
4. 在页面批准后，`ryn_set_model_sharing` 写入真实加密来源配置。
5. 再次 `ryn_list_models` 核验：`shared_models` 仅包含 `acceptance-model`，`second-model` 仍私有。
6. 总共 4 次模型调用、3 次工具执行。浏览器刷新可读取同一任务和回执。

布局检查包含 1024×768 桌面宽度与约 560px 窄视口；主导航、任务列表可独立收起。原手动聊天带参数链接保持兼容。首次关闭助手时仍有模型配置入口。

## 真实模型的负向兼容验证

已安装、已登录 Codex CLI 在隔离节点通过普通聊天自检。真实只读工具任务却返回工具环境不可用，没有实际调用工具；显式两轮能力探测再次失败。最终目录如实返回 `available=true, agent_supported=false, tool_support=unsupported`。

修复后 Codex 不再凭适配器名字自动获得工具能力；必须通过当前 CLI 二进制的显式能力测试。未开放提供节点的 Shell/文件/插件或宿主工具来绕过限制。普通推理仍可使用。该试验是兼容性边界验证，不是“八成能力”效果评测。
