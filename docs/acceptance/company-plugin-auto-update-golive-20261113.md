## 服务端部署

- 只新增一个编译后的接口文件 `rynUpdates.controller.js`（sha256 `d59b36b1…81e8`），不替换任何现有文件；compose 增加一行只读挂载；重启后 7 秒就绪。
- 包目录使用默认的 `/opt/ryn-updates`（容器已挂载），未改环境变量。
- 部署前在容器内用真实编译文件加替身登录做探测：未登录 401、错误令牌 401、清单 200 且不缓存、文件块 200 且长期缓存、Range 返回 206、符号链接和越界路径 404。部署后对线上文件重复一次，全部通过。
- 公网未登录请求：部署前 `400 invalid_request`，部署后 `401 invalid_token`。
- 回滚：部署目录内 `sudo python3 deploy.py rollback`（删除接口文件、恢复 compose、重启）。

## 本机实测（真实服务器、真实密钥、真实登录）

本机 Ryn 0.9.1 原先没有更新源。本次没有重装，只写入安装包本应写入的 `plugin-services/updates.json`（内容取自 11-12 构建的安装包，地址与公钥已核对），然后通过本地接口触发，等同于在设置页点“检查更新”和“立即更新”。

| 步骤 | 结果 |
| --- | --- |
| 检查更新 | 用公司账号登录令牌请求成功，令牌来源与更新地址同源；状态变为“已下载好”，显示更新说明 |
| 增量下载 | 实际下载 76,092,598 字节，占整包 29%；其余文件复用旧版并逐个校验 |
| 立即更新 | 10 秒内切换完成；健康检查返回版本 `2026.11.13.83726` 和修订号 `5a38b83…`，状态“已是最新” |
| 更新后 | 三个插件保持启用；公司登录保持已绑定；账号、工作台、目录接口 200；Dashboard 连接就绪、60 个工具、无只读提示候选；4 个公司技能在位 |
| 旧版 | 上一版运行目录保留，可回退 |

说明：

- 旧版运行时（源码 `410720e`）没有版本号，更新器按“可升级”处理，符合预期。
- 联盟营销的两个连接显示“需要授权”。这两条记录最后修改于 11-09 和 11-10，本次更新没有改动它们；更新前的状态没有留存，无法对比。
- 本机回滚材料（更新前的 `services.json` 和扩展配置）保存在仓库外。
