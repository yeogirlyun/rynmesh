## 结果

- 69 项在本分支全部通过（Windows 虚拟机，串行与 `-n 4` 均跑过）。
- 3 个产品修复，其余为测试/验收脚本适配；没有放宽安全、审批、回执、像素保真断言。

## 产品修复

1. **任务分叉长路径**（`task_forks._write_copy`）：结果/附件目标接近 260 字符时 `os.rename` 报 WinError 3，折叠成 `agent_fork_storage_unavailable`。改用 `atomic_io.fs_path` 长路径形式；仍为只建不覆盖。覆盖 4 个历史用例，并新增固定长路径回归测试（修前失败）。
2. **小窗口工具菜单**（`tool_menu.project`）：≤16 KB 窗口本应把计划/输入/结果等控制工具放进发现目录（约 0.9 KB），但"目录是否划算"按全部控制工具（约 10 KB）计算，小注册表时选了全量模式、多发约 3.4 KB，挤掉历史；表现为同一用例在某些上限下失败、更小或更大反而通过。新增回归测试（修前失败）。
3. **对端模型预算**（`models.py` + `output_policy`）：对端提供方按"UTF-8 字节 + 输出 ≤ 窗口"（1 字节算 1 token）准入，Agent 却按 3 字节/token 预算，长请求被提供方 HTTP 400 拒绝（`agent_inference_failed`），而不是先压缩。对端模型行现在声明 1 字节/token，上下文预算和输出上限按此计算；任务 token 估计不变；提供方准入未放宽。本机服务在进程内调用、没有该检查，保持原估计。

## 测试与验收脚本适配（要点）

- 基础提示词从 ~2.65 KB（固定上限 8000/10000/12000 设定时，f160665）增长到 ~7.7 KB。`fit_window()` 按"历史上限 + 实测提示增长"设定，保持原场景的历史空间与压缩压力。
- 默认权限已是 automatic、默认不做独立核验：需要审批/核验的场景（C01、C03、R02、P03）显式设 `confirm_changes` / `verify_text_responses`。
- 脚本化规划器把所有无工具请求当核验器；目录/设备列表会触发真实上下文检查点。现在会回应检查点、恢复服务器固定的写入回执、记录已完成步骤，避免压缩后重复写入（R02 曾重复分享 3 次）。
- 子进程用例显式传入本工作树 `PYTHONPATH`；QuickJS 假 worker 不再在 ready 后 0.5 秒自动 EOF（导致并发握手失败与活动会话数不稳），观察线程不再空转抢 GIL（该用例 70 秒 → 2 秒）。
- 其余为过时契约：错误码改名、原图不再缩到 512、`agent_supported` 与 `tool_support` 分开断言、按需加载工具先经发现、流式增量合并、最终文本逐字节保留等。
