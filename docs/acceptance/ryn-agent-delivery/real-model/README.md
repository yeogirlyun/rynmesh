# T01：真实主控模型基线

日期：2026-10-09。本目录保留原始运行、修复后的候选运行和离线判定，不只保留成功样本。这个窄场景不代表完整 Agent 或“八成能力”已经交付。

## 来源与测试边界

- 使用运行节点已经配置、启用的 Z.ai `glm-5.3-flash`。通过现有 `SourceStore` 只读加载授权凭据，只在内存中的真实 `SourceAdapter` 使用；没有修改运行节点来源或分享规则。两批运行均使用真实远端推理，没有预设模型回答。
- 每次任务新建隔离 Ryn home、身份、个人空间、加密来源配置和 Agent 状态；复用实际 LLM 服务、模型目录、桥接、运行时和五个业务工具。该服务栈没有启动 HTTP 监听器，没有浏览器或两个物理节点参与。
- 测试来源包含真实主控模型与 `private-fixture-model` 私有哨兵。哨兵只是配置隔离检查项，没有假称它是可调用的真实上游模型。真实主控的能力在每批业务运行前用两轮工具请求/结果续写验证。
- 注册及 LAN 发现关闭；只在临时个人空间修改分享配置。`publication=published` 是本测试的本地发布路径回执，不是公网注册或远端消费成功证据。
- 同一用户目标要求检查模型、设备、服务；仅分享主控模型、读回确认；再撤销并读回，保留默认模型与兄弟模型私有。两批共六轮的用户目标完全相同，没有逐轮人为指导模型选工具或纠错。
- 测试程序只批准两个符合预期的操作：指定隔离模型先 `enabled=true`、后 `enabled=false`，且范围是当前个人空间。它不生成模型调用，也不改变模型响应；审批轨迹全部保存。
- 每任务上限：16 次模型调用、600 秒活跃时间、100000 上下文字符、20000 输出字符；桥接最大生成 4096 token。实际费用未知；工具探测 usage 未采集，业务调用 usage 单独列出，不能冒充完整费用。

前两轮通过业务状态和报告检查，各 6 次模型调用、9 次成功工具操作、零拒绝，耗时 100.625 与 80.312 秒。第三轮分享后，第 4 次模型请求耗时 122.312 秒后抛 AdapterError，任务失败，未执行撤销及最终核验；该批只有 2/3 通过。原 harness 没有保留安全错误 code，不能倒推具体上游原因。测试栈关闭后，由 harness 单独清理临时分享，记录在 cleanup.json，不算模型成功。

## 判定方式

`check_evidence.py` 不调用模型。按事件序号检查：初始两模型私有 → 成功分享 → 读到目标已分享/兄弟私有 → 成功撤销 → 读到两模型私有。单列成功执行和明确未执行拒绝，检查两次审批、实际来源状态快照、默认模型不变，以及不同运行的上下文不包含另一运行的模型身份。

最终文字另外逐份人工审阅，尤其检查操作号、前后状态、设备证据边界和是否冒充完成。模型输出只作为待审内容；不会用自己的“成功”结论给自己评分。两种读取工具复用同一目录，并非两个独立数据源；harness 另直接读取真实加密来源配置作为独立状态证据。

```powershell
.venv/Scripts/python docs/acceptance/ryn-agent-delivery/real-model/check_evidence.py docs/acceptance/ryn-agent-delivery/real-model/20261009T083447Z
```

`run_baseline.py --live --source-id <本机既有来源ID>` 会产生真实调用；不作为默认自动测试运行。重跑必须保留所有新记录，不能覆盖旧批次。每份结果须扫描当前实际凭据和 `reasoning_content`，不输出凭据本身。
