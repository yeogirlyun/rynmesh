## 打包验收（VM，安装包里的节点程序）

这台 VM 没有真实模型，用三样东西代替：

- **假模型服务**（`fake_openai.py`，OpenAI 兼容）：`vision-sim` 能看图（图片测试回答 "red"）；`text-sim` 收到图片就返回和 DeepSeek 一样的 400 错误（`unknown variant image_url, expected text`）。
- **假插件**（`fake_mcp.py`，stdio MCP）：`fake_write` 没有声明只读，调用时返回 `isError`（"invalid date range"）。
- **打包后的节点**：`build-windows.ps1` 打出来、装进安装包的 `rynmesh-peer.exe`（和安装包里的那份 SHA256 相同），用独立的 `RYNMESH_HOME` 无界面运行；脚本 `accept.py` 通过界面用的同一套 HTTP 接口操作。

脚本和报告放在 VM 的 `C:\Users\sguser\ryn-worktrees\_accept\stability-final\`（不提交：含运行数据）。

## 按代码核对、没有实测的

- **共享模型发大图：** 共享线路 v2 一次最多 6 MB 图片。三条传输路径的上限都容得下：局域网直连由共享方的推理入口限 16 MB（`llm_package/safety.py` `MAX_REQUEST`）；P2P 通道单条消息 32 MB（`llm_package/p2p.py`）；中继走加密文件上传，不受 2 MB JSON 上限约束。`peer_http.py` 的 2 MB 只限制回复。没有用两台电脑实测，在 `test_shared_image_carrier`、`test_shared_model_parity` 里用真实的共享方代码（加密请求 → `ProviderService.handle` → 适配器）验证 3.46 MB 截图原样到达。
- **方案第 6 节验收表里只能在界面上看的项**（Excel 粘贴、错误说明和按钮、看图图标、只读确认卡片、断网自动恢复）：有前端单元测试，没有在真机界面上操作。
- **S5 网络抖动**仍是全局提示（见方案第 8 节），但每 3 秒和网络恢复时自动核对，不用手动点。
