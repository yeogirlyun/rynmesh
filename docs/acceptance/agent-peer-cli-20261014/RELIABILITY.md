# Ryn Agent 实机排查与修复

日期：2026-10-14。对象：本机子陵台式，以及局域网 Windows 172.16.8.82。

## 已确认的问题

1. **工作目录没有实际绑定。** 本机任务 `agent_146b5901861a448ba766e3b0b963cd65` 的用户补充信息含 `E:\DCIM`，但任务保存的 `local_execution.workspace_root` 为空。普通聊天信息不会自动授予文件访问权限；旧界面没有给出可用的当前任务绑定入口。已增加“使用此目录并继续”，通过带版本检查、幂等控制的本机接口显式绑定，再续接原任务，修改文件仍需确认。
2. **Codex 临时目录并发删除导致整个任务崩溃。** 续接原任务后真实复现 `FileNotFoundError`，栈落在 `codex_session.receive → private_storage_bytes → os.scandir`。CLI 会删除已经加入扫描队列的临时目录。现在允许扫描过程中消失的子目录，仍对整个私有工作区丢失报错，也保留外部符号链接不跟随的限制。加入确定性回归测试。
3. **安装版长回复的事件读取器失败。** 多次真实失败的栈落在 `CodexRPC.receive` 的读取器失败分支。此前无用的逐字输出事件也全部进入容量为 256 的队列，消费者逐个执行磁盘检查；现在只转交实际消费的完整消息、用量和结束事件，并保留所有请求/响应及执行边界事件。2,048 条增量事件的回归测试确认不会挤掉最终消息或隐藏执行请求。此前分支将队列满和解析错误合并记录，因此不能从旧记录进一步区分每次失败的类型。
4. **Windows 临时目录清理错误覆盖模型结果。** 实机再现 `tempfile` 清理阶段的 `PermissionError`。允许占用文件导致的临时清理失败，不让它覆盖模型结果或原始异常；带标记的残留目录仍由现有过期清理回收。
5. **原先的通用错误缺少排查证据。** 增加仅包含异常类型、代码文件名、函数和行号的运行时事件，不保存异常文本、局部变量或凭据；包装后的推理错误也保留其原异常的代码位置。Codex 超时、断连、上游失败、无效工具提案分别归类；无效提案在不执行任何工具的前提下进入已有的一次格式纠正流程，并保留用量记账。
6. **普通聊天不应启动工作流程。** 收紧系统提示及工具目录，按用户语言回答。普通文字回复不再额外调用一次模型核验；界面仍将其视为未独立验证，实际工具任务保留核验。高级设置可开启文字回复核验。
7. **共享模型身份被普通设备信息更新误伤。** 授权版本与设备名、租约等普通快照变化分开，角色撤销、成员移除及恢复仍改变授权身份。缺失目录时只刷新已签名的模型元数据；不会暗中切换已有任务模型。
8. **多次发现与模型调用增加延迟。** 仅缓存不可信注册表定位结果 10 秒，授权目录仍实时检查；Agent 调用优先已发现的 LAN 地址，保留严格 P2P、端到端加密及禁止保留请求的路径约束。
9. **单轮时限无法在任务预算中调整。** 旧任务保留了 180 秒单轮限制，生成文件后的检查实际超过此限制；原界面只能改累计时限。现在预算页单独提供单轮时间输入（10–3600 秒），带版本检查、幂等和空闲状态校验，不自动继续任务、不清空累计用量。本任务明确调整为 900 秒。
10. **任务自检把后续只读活动误判为状态失配。** `ryn_diagnose_current_task` 的读取次数、只读操作列表和核验结果本来会随执行改变。自检现在不再把这些当作不变量；任务状态、错误及写入派发事实仍比较。其他任务的诊断比较保持原逻辑。保留旧的失败验收记录，未改写历史结果。
