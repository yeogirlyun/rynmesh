# 多设备同步开发记录

状态：基础数据层开发中，尚未接入应用入口、设备配对或网络传输；不是产品验收通过声明。

## 本轮实现

新增 `rynmesh/device_sync/records.py` 与 `store.py`：

- 收藏、阅读进度和会话使用每个内容实体的设备计数器与并发值。合并不依赖机器时间，重复和乱序快照可收敛。
- 收藏并发新增/取消时取消优先，但保留冲突来源；看到合并结果后明确再次收藏可以恢复。删除的操作记录不会随旧快照回来而丢失。
- 阅读进度按操作的因果顺序处理，向前重读也有效；并发位置保留多个候选，不使用最大百分比代替用户选择。材料版本标识可随位置记录。
- 会话保留原 Provider、服务键、网络和创建身份。并发续聊形成分支，提供共同消息前缀；删除与新增并发时，新增分支进入恢复项。明确擦除会话会删除恢复正文并保留阻止旧投递复活的标记。
- 收藏和阅读只允许明确的元数据字段，正文、摘要、图片地址和任意扩展不进入同步值。会话仅保留已终结消息与材料引用，排除草稿、凭证、运行中消息及其关联请求。
- 存储复用节点消息密钥、现有加密模块、进程共享文件锁和原子写入，使用独立加密通道。文件位于节点 `device-sync/replica.json`，未知版本拒绝修改，本地未知扩展字段保留且不进入发送批次。
- 调用者必须明确指定同步范围；没有范围时不产生发送批次。批次最多 100 条、12 MiB；整个批次存储成功后才返回确认。过期确认不会把较新的本地记录标成已同步，重新配对前可以清除旧确认。

当前上限为 64 个设备标识、合计 3 万个实体（含删除记录）、单实体 8 MiB、总明文 128 MiB。达到限制会拒绝本次操作并保留旧数据，不自动清除删除记录或冲突正文。这些上限还需要在后续产品页面中明确展示。

## 证据与限制

环境：Windows，本地 Python 虚拟环境，真实临时目录与加密密钥；全为合成数据，无外部请求。

- 合并测试覆盖并发取消/再收藏、向前重读、并发位置选择、三台逻辑设备的重复乱序组合、会话共同历史与分支、删除恢复项、擦除后旧快照拒绝、同一操作身份的冲突正文拒绝，以及元数据范围限制。
- 存储测试覆盖选择范围、接收成功但确认尚未返回、过期确认、写入前失败、写入已提交但响应丢失后的重启重试、八个实例竞争同一修订、未来/损坏文件保留、本地扩展保留与发送字段过滤。
- 两份真实加密存储预置各 1 万条已经相互确认的记录后，新增 100 条，按 `write_many → pending → receive → acknowledge → pending=0` 计时。第一次 3.636 秒，追加确认校验后的复测 2.864 秒。初始基线由测试直接构造；不包含初始合并、来源适配、设备握手、HTTP 传输或页面渲染，不能据此宣称 SYNC04 已通过。
- 第一轮新模块检查 26 passed，8.19 秒；随后与现有 Ask 材料、阅读记录的相关回归 46 passed / 1 warning，12.11 秒，Ruff 通过。警告为既存的 TestClient 弃用提示。之后补充同一操作的数值编码变化保护：不能因 Python 把 `0` 与 `0.0` 判成相等，让不同顺序合并得到不同哈希；最终新模块专项 27 passed，6.81 秒，Ruff 通过。

## 接入必须满足的约束

1. 本地收藏、取消、进度和会话修改，需要在同一次可靠写入中保存对应的同步操作身份和所见版本。不能仅定时比较最新值，否则中间操作及因果关系会丢失。原存储升级需备份，来源清理和列表淘汰不能误删同步删除记录。
2. 接收端把变更落到真实收藏、阅读和会话来源后，才能向另一设备确认产品层完成。当前 `ReplicaStore.receive` 的确认仅证明副本存储已持久化，接入层不得提前把它当作页面数据已更新。
3. 设备配对必须独立于好友关系，两端确认身份、邀请时效/一次性、选定范围、加密认证完成后才允许传个人数据。当前内部方法没有提供此授权，也不能直接作为公开 HTTP 端点。
4. 配对移除、暂停、范围关闭及重新加入需要实际状态机；`pending` 的范围过滤和确认清理只是所需组件，不能替代身份撤销。
5. 冲突选择需要核对用户已审阅的修订；会话恢复需明确创建新分支身份，不恢复旧删除身份。不复制运行中任务，也不得自动换服务重发历史。
