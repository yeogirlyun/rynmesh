# 多设备同步开发记录

状态：收藏/阅读及会话来源、Ask Ryn 分支恢复、“我的设备”双端配对和范围控制已接入开发分支；尚未接入个人内容传输与完整同步状态，不是产品验收通过声明。

## 本轮实现

新增 `rynmesh/device_sync/records.py` 与 `store.py`：

- 收藏、阅读进度和会话使用每个内容实体的设备计数器与并发值。合并不依赖机器时间，重复和乱序快照可收敛。
- 收藏并发新增/取消时取消优先，但保留冲突来源；看到合并结果后明确再次收藏可以恢复。删除的操作记录不会随旧快照回来而丢失。
- 阅读进度按操作的因果顺序处理，向前重读也有效；并发位置保留多个候选，不使用最大百分比代替用户选择。材料版本标识可随位置记录。
- 会话保留原 Provider、服务键、网络和创建身份。并发续聊形成分支，提供共同消息前缀；删除与新增并发时，新增分支进入恢复项。明确擦除会话会删除恢复正文并保留阻止旧投递复活的标记。
- 收藏和阅读只允许明确的元数据字段，正文、摘要、图片地址和任意扩展不进入同步值。会话仅保留已终结消息与材料引用，排除草稿、凭证、运行中消息及其关联请求。
- 存储复用节点消息密钥、现有加密模块、进程共享文件锁和原子写入，使用独立加密通道。文件位于节点 `device-sync/replica.json`，未知版本拒绝修改，本地未知扩展字段保留且不进入发送批次。
- 调用者必须明确指定同步范围；没有范围时不产生发送批次。批次最多 100 条、12 MiB；整个批次存储成功后才返回确认。过期确认不会把较新的本地记录标成已同步，重新配对前可以清除旧确认。

当前上限为 64 个设备标识、合计 3 万个实体（含删除记录）、单实体 8 MiB、总明文 128 MiB。达到限制会拒绝本次操作并保留旧数据，不自动清除删除记录或冲突正文。这些上限还需要在后续产品页面中明确展示。

## 接入必须满足的约束

1. 本地收藏、取消、进度和会话修改，需要在同一次可靠写入中保存对应的同步操作身份和所见版本。不能仅定时比较最新值，否则中间操作及因果关系会丢失。原存储升级需备份，来源清理和列表淘汰不能误删同步删除记录。
2. 接收端把变更落到真实收藏、阅读和会话来源后，才能向另一设备确认产品层完成。当前 `ReplicaStore.receive` 的确认仅证明副本存储已持久化，接入层不得提前把它当作页面数据已更新。
3. 设备配对必须独立于好友关系，两端确认身份、邀请时效/一次性、选定范围、加密认证完成后才允许传个人数据。当前内部方法没有提供此授权，也不能直接作为公开 HTTP 端点。
4. 配对移除、暂停、范围关闭及重新加入需要实际状态机；`pending` 的范围过滤和确认清理只是所需组件，不能替代身份撤销。
5. 冲突选择需要核对用户已审阅的修订；会话恢复需明确创建新分支身份，不恢复旧删除身份。不复制运行中任务，也不得自动换服务重发历史。

## 收藏与阅读来源适配

新增 `reading.py`、`reading_bridge.py`，并接入 `ConsumptionStore` 的实际读写：

- 内部显式启用后，收藏/取消和阅读位置在同一次原子写入中保存操作身份。尚未提供用户启用入口；普通安装保持原来的本地格式，不自动开始同步。
- 旧记录升级前完整备份，保留本地扩展字段；未来版本拒绝修改。备份采用阅读存储自己的 96 MiB 上限，已覆盖超过通用 16 MiB 限制的旧文件。新增信封最多 256 MiB、收藏与阅读共 2 万个实体（含删除记录），容量不足时保留原文件。
- 最近历史的淘汰不会删除同步操作或仍在使用的收藏/进度；清空会保存因果删除标记，旧快照不能恢复已经观察并删除的数据。这里只处理阅读/收藏，不能代替 G08 的全应用擦除。
- 普通阅读保留未处理的其他设备位置；明确选择须携带审阅过的修订。第三台设备首次收到冲突时只显示元数据和冲突状态，不任选一个候选位置。候选查询已在内部来源接口中提供，页面选择入口待接入。
- `ReadingBridge` 按“来源保存 → 加密副本保存 → 返回确认”处理接收。两步之间失败不返回确认，来源中已提交内容仍可读，重启后可重复投递。发送准备及确认处理前会补齐本机来源，防止过期确认把后来发生的本地修改标成已同步。
- 副本损坏不会阻止正常本地阅读写入；修复副本后可从来源补齐。构造适配器不会授权设备，不会启用范围；来源身份必须与节点副本身份一致。来源与副本采用统一的锁顺序，网络调用不在锁内执行。
- 现有本地阅读 API 可携带内容版本和审阅修订；过期修订返回 409，存储不可用返回 503。保存操作放到工作线程执行，等待存储时健康检查仍可响应。未增加可绕过配对的远程同步路由。

新增真实临时文件测试覆盖迁移/备份失败、历史淘汰、写入前失败、提交后响应丢失、重启重投、并发收藏与位置、第三端冲突、明确选择过期、向前重读、清空后旧投递、元数据过滤、八个来源实例并发、来源/副本分别失败、过期确认和锁顺序。没有外部网络、真实双桌面或 GPU 测试。

验证结果：来源与桥接最初专项 53 项（修正一条断言：仅同步收藏的接收端取消后可直接从列表消失），最终通过。随后后端全量 `pytest tests/ -q` 为 **1158 passed / 29 skipped / 5 warnings，213.82 秒**。在此后补充大文件备份、备份失败、HTTP 修订冲突与非阻塞保存检查，最终六个相关测试模块 **85 passed / 1 warning，14.94 秒**，涉及修改文件的 Ruff 通过。全量结果不包含后补的四个用例；后补变更以这次专项回归为证据。警告均为现有 TestClient/FastAPI 弃用提示，跳过项不算验收通过。

## 会话来源、运行中任务与恢复入口

新增 `conversations.py` 与 `conversation_bridge.py`，在 `ConversationStore._write` 统一捕获来源变化，因此后台 `AskRunService` 归档结果也与同步操作一起提交。

- 显式启用时备份原加密文件并升级到 v2；不会自动启用或传输。来源记录、候选分支、恢复映射继续加密，保留未知本地扩展且不发送这些扩展。普通历史仍采用原来的容量预算；启用同步后为 64 MiB 明文、88 MiB 加密信封，最多 1000 个会话和 10000 个因果实体（含删除记录），达到限制拒绝操作并保留旧文件。
- 正常写入沿本机所见分支继续；远端并发分支单独保留。第三台逻辑设备仅收到冲突时不会任意挑一条放进普通历史，候选在专用列表中完整可读。恢复必须审核修订，并创建新会话身份，保留原 Provider/服务键/网络。
- 运行中修改、问题及自动标题不会提前进入同步。初次启用发生在运行中时，也会过滤未完成输入与自动标题。远端更新不会替换正在使用的上下文；本地结果完成后保留并发分支。
- 远端普通删除会隐藏原会话并请求取消原任务，避免新请求继续使用已删除身份；原任务仍按原 ID 对账，不重发。已经发生的迟到结果进入恢复项，不回到主历史。明确的因果擦除则不保留迟到正文。
- 远端删除时，本机未发送草稿留在本机恢复区，并保留原服务绑定。它不进入同步批次；用户可单独保留为新会话。个人导出在一个来源锁内取得普通历史、草稿和恢复项的一致快照。
- 桥接层依然先保存来源、再保存副本、最后确认；源归档或副本写入失败不会确认，重试可恢复。旧确认不会覆盖后来完成的本地回答。
- Ask Ryn 增加分支与恢复区：分别展开完整正文、显示原接收者、保留为独立会话，无模型也能阅读。恢复使用审核版本和稳定的新身份，刷新/响应丢失后重试不会重复新增；恢复后焦点和页面定位到新历史。聊天页在出现其他设备变更时提供复核入口，删除说明同步范围及并发恢复项。

安全边界：没有开放远程同步写入或自动配对。本地历史/恢复 API 继续受 owner 控制，恢复不会调用模型。当前内部 `sync_erase` 只实现来源的因果擦除；**尚未完成迁移备份、旧副本、浏览器恢复副本和订单结果的统一擦除与远端确认**，因此未提供产品“全部擦除成功”按钮，G08/SYNC13 仍未通过。保留分支后原冲突仍可复核，关闭/丢弃恢复项的完整产品流程待补。

## 双端配对、范围控制与移除

新增 `pair_crypto.py`、`pair_store.py`、`pairing.py`、`routes.py`，页面入口为 Settings → My devices（`/devices`）。

- 邀请签名绑定节点身份、消息密钥、范围与有效期；默认 15 分钟，一次只能绑定一个加入请求。新电脑先审核邀请，原电脑再审核请求，两端核对相同代码。接收请求、批准、收到能力秘密、确认回执分别持久化，不能把收到请求当成配对成功。
- 加入与确认请求先写入加密容器再发送。回执丢失、进程重启、邀请过期后已提交的最终确认重试不会重复配对。改名不改变密钥身份；同一电脑或已活跃设备不能重复配对。过期、取消、篡改邀请与错误接收者均拒绝。
- 三类范围默认不勾选，两端有效范围取交集。暂停、范围变化采用各自递增修订；恢复后旧修订不能授权数据写入，不依赖两台电脑时钟一致。授权上下文持有配对锁直至本地来源提交，移除和范围收缩与该提交串行；网络调用不持有此锁。
- 移除先在本机保存拒绝状态、清除能力秘密，再由共享后台任务送出签名加密通知。对端提交后才确认送达；回应丢失可重试，重新配对使用新的配对身份，旧移除通知不会删除新配对。页面明确说明已复制内容无法收回。
- 复用现有 Ed25519、消息密钥和加密传输原语；配对、策略、移除与磁盘容器使用不同通道。磁盘只保存加密信封，公开状态不含秘密或完整握手报文，未知本地扩展保留。未来版本、坏密文或无效策略拒绝修改并保留原文件。
- 容器目前上限为各 256 条邀请/配对、8 MiB 明文、12 MiB 加密文件；无自动清理。网络报文最多 64 KiB，使用受限 IP 地址、5 秒超时和有界响应；每来源每分钟最多 60 次控制请求，来源缓存最多 256 项。尚未提供地址变更、旧邀请清理和容量管理的完整产品流程。
- 新设备缺少可达地址时返回可解释状态，不阻止整个应用启动或本机移除已有设备。开发环境可显式使用 `RYNMESH_DEVICE_ENDPOINT` 与 `RYNMESH_DEVICE_ALLOW_LOOPBACK=1`；这些只用于本次隔离测试，不算无需配置的打包体验验收。
- 所有来源适配器尚未连接到配对传输，接口明确返回 `data_transfer_available=false`，页面显示开发状态，**不会把配对成功显示为内容已同步**。好友权限、模型权限与个人内容没有因配对自动复制。
