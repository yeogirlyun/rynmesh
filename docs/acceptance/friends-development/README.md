# 配对与消息开发验证

日期：2026-09-11。分支：`codex/user-product-development`。这是开发证据，SHARE01–11 尚未完整验收。

## 当前实现

- 从 `feature/user-requirements-suite` 复用好友模型和页面样式，统一到独立 `friends` 路由包；保留主线邮箱、Transport、后台任务注册表与原子写入。
- 一次性邀请先在本节点验证，再由用户确认联系邀请者。邀请文本包括安装链接、有效期和粘贴步骤，二维码在本机生成。
- 接受邀请和保存关系在一个事务中完成；并发接受仅一方成功。同一接受者丢失响应后重试可恢复原关系。接受结果和失败原因均验证邀请者签名。
- 文本和小附件先持久化，再传输。消息身份在重试时保持不变；接收方持久化后才签发送达回执，普通 HTTP 成功或进入邮箱均不算送达。
- 离线消息和撤销通知接入已有加密邮箱。撤销先原子保存通知并移除访问凭证，远端确认后再结束通知状态。重复收到通知或回执不会重新授权。
- 消息状态区分待发送、邮箱待确认、已送达、失败和过期。附件直连上限 5 MiB；邮箱封装上限 64 KiB，超限等待直连。
- 前端支持好友列表自动更新、邀请审核、消息和附件、同身份发送重试、主动保存附件以及撤销副本说明。

## 浏览器实际操作

00:03–00:07（UTC+8），在 Codex 浏览器打开两个独立本地节点，地址分别为 `127.0.0.1:18841` 与 `127.0.0.1:18842`。节点使用新建临时目录；后台来源发现关闭，模型 Provider 为 none。

1. A 页面创建邀请，显示安装说明、有效期和本地二维码。
2. B 粘贴整段说明，页面正确提取邀请并显示签名身份、待访问地址和权限；点击接受后显示好友。
3. B 通过页面发送中文验收消息，显示“Delivered · confirmed by your friend”；A 刷新并打开会话后看到相同正文和 Received。此路径使用真实 HTTP Transport。
4. 重载 B 页面后，好友关系与已送达历史仍可重新打开。
5. B 撤销测试关系，确认界面明确说明本地立即生效、远端通知和已保存副本不可收回；确认后好友从活动列表移除。

视觉检查发现二维码过小，随后调大显示尺寸和留白。邀请者列表增加轮询，以便自动显示接受结果。
