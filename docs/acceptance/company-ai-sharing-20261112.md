这一轮做了什么：

1. **免扫码换取通道授权（公司中心）。** 已经登录过公司插件的设备，可以用那次登录向公司中心换一份只用于同事通道的授权。每台设备各自一份，不占设备名额，原登录被吊销时一起失效。没有采用旧分支里的写法（同一人的多台电脑共用一份授权）。
2. **身份比对改对了（Ryn）。** 公司中心在绑定结果和目录里返回调用者自己的公司账户编号，Ryn 用它和插件登录的账户比对。归属未知的旧绑定不算匹配，由后台刷新自动补上。
3. **发布人判断。** 公司中心在目录里声明「你是不是发布人」，Ryn 只认这一条。发布人名单已配置为老板一人。
4. **原有缺陷：通道接口取不到请求体。** 线上「发起绑定、确认绑定、发布模型」三个接口用框架的参数注入取请求体，在生产环境里取到的是空值，一直返回 `invalid_request`；线上绑定表此前一直是空的，说明这组接口从未成功过。改为直接读取请求体（与线上正常工作的 MCP 接口同一写法）后绑定成功。这个问题在单元测试里看不出来，因为单元测试直接调用服务。
5. **线上文件与仓库有差异。** 线上有手工修改，也缺少仓库里一些未上线的功能，所以没有整文件替换，而是把本次改动逐处拼接到线上文件上，逐行核对后只多出本次的内容。

**关于「同事不用扫码」，实际情况是分两种：**

- 设备上已经有公司中心签发的登录（目前是 Dashboard 的那次扫码）的同事：不用再扫码，通道自动建立。老板的主机属于这种，已实测。
- 只用工作台、从没在公司中心登录过的同事：工作台的企业微信登录是插件本机服务自己完成的，公司中心并不知道这个人。这类同事需要在公司中心登录一次（扫码），而且公司中心现在是审批制，第一次还要管理员批准。这是公司中心现有的成员准入方式，本次没有改。

## 更正（11-12 晚补充核实；其中的问题已在上一节解决）

在老板的主机 Ryn 和线上公司中心上补充核实后，发现本记录下文有两处结论是错的，另有一个原有缺陷会挡住本功能。**按现在线上的公司中心，本功能还不能用。**

1. **「同事不用再扫码、不用点连接」不成立。** 用插件登录凭据自动换取 `peer.connect` 会话、以及公司中心的工作台接口（告诉 Ryn 当前用户是不是发布人），只存在于公司仓库一个未合并的分支（`codex/local-only-overbroad-snapshot-20261102`）里。`develop` 和线上部署的公司中心都没有这两项。我最初是在主工作区读的代码，那里正好检出的是这个分支，没有核对它是否已合入。
2. **「公司同事」勾选在线上不会出现。** 勾选是否显示取决于公司中心的工作台接口，线上没有这个接口，Ryn 得不到「是发布人」的答复，就不显示。
3. **原有缺陷：身份比对用错了编号。** Ryn 对公司插件的每个通道操作都会比对「插件登录的人」和「通道绑定的人」。前者是企业微信 userid，后者是公司中心返回的内部成员编号（UUID），两者永远不相等，所以即使登录并绑定成功，发布、目录、工作台这些操作也都会被 Ryn 自己拒绝（`peer_provider_login_required`）。这段比对不是本次引入的，但本次没有发现它。

主机实测（只读）：Ryn 登录的是老板本人的公司账户；公司通道状态是未登录、未绑定；触发自动同步返回 `peer_provider_login_required`。

要让本功能可用，需要二选一（等老板决定）：
- 把公司中心那个分支里的两项能力合入并部署（这是「不改公司中心」之外的事），同时修正上面第 3 点；或者
- 只改 Ryn：修正第 3 点，改用别的办法判断发布人，同事各自点一次「登录」完成 `peer.connect` 授权。

下文「同事的实际连接流程」一节和 B 中「公司中心说当前用户是发布人」的前提，都以本节为准。

## 同事的实际连接流程

同事装好公司插件并用企业微信登录后，**不需要再扫码，也不需要点「连接」**：Ryn 后台每 30 秒用插件已有的登录凭据向公司中心换取 `peer.connect` 会话（公司中心已实现这种换取方式），然后自动绑定本机并读取目录。「公司共享」分组随后出现在模型列表里。只有插件登录本身失效时才需要重新登录。

## 已知限制

- 每台提供方电脑只能看到自己共享出去的那部分用量，看不到全公司汇总。
- 用量按设备记录，再通过公司目录对应到人。同事离职或设备解绑后，旧记录显示记录当时保存的名字；从未取到名字的显示「未知设备」加设备号前 8 位。
- 「今天」按 UTC 日期切换（北京时间早上 8 点），和 Ryn 现有用量卡片一致。
- 公司通道里 CLI 只共享默认模型，同事不能在 Codex 的多个模型之间选择（公司目录不带 CLI 的模型清单，改它需要动公司中心）。
- Claude CLI 本身只支持对话，不支持 Agent 工具，共享出去也一样。
- 模型原有的「共享 token 每日上限」如果之前设置过，对公司同事的调用同样生效；本次没有新增任何限额。
- 公司插件主工作区（`codex/local-only-overbroad-snapshot-20261102` 分支）里有别人未提交的 `CompanyFinanceApp.tsx` 改动，以后合并时会和本次删掉的那一段冲突，需要保留「删除开关」的结果。
- Ryn 仍保留 `models.share` 这个插件入口，旧版插件可继续调用。

## 上线后的切换步骤

1. 在公司中心配置发布人名单（老板和管理员的 userid），重启公司中心。
2. 老板和管理员装新版 Ryn，同事装新版 Ryn 和新版公司插件。
3. 老板在 Ryn 的 AI 池子里，对要共享的模型勾选「公司同事」。
4. 找一两位同事试用：在模型选择器的「公司共享」分组里选模型，发一条消息，再让 Agent 执行一次工具，确认命令是在同事自己的电脑上执行的。
5. 老板在 AI 池子的「公司同事用量」里确认看到了这几位同事。
6. 确认没问题后，把同事从家庭组里移出。老板自己的家庭组设备照常使用。

回退：取消「公司同事」勾选即可立刻停止共享；在移出家庭组之前，同事原来的用法不受影响。
