# Rynmesh 非模型 API 选型

更新：2026-09-21。以下是开发建议，不代表已经实现。

**定位：一人部署，多人调用；每个节点都能贡献服务。只开放固定 API，不开放电脑控制权。**

| 能力 | 用户能做什么 | 是否适合当前项目 | 主要原因 |
| --- | --- | --- | --- |
| 文件转换 / PDF | Word 转 PDF、合并拆分、格式转换 | **优先做** | 有任务与文件传输基础，可接成熟转换引擎 |
| 网页正文 / RSS | 输入网址，返回正文或更新列表 | **优先做** | 已有阅读提取与来源管理基础，需封装为服务 |
| 商品 / 招聘 / 社媒数据 | 查询价格、职位、公开内容 | **有条件做** | 先选一个允许使用且可持续维护的数据源 |
| 地图与路线 | 地址查坐标、算路线和距离 | **有条件做** | 可部署现成引擎，但需维护区域地图数据 |
| IP / ASN 查询 | 查询地区、运营商、网络归属 | **有条件做** | 需可授权使用的数据库；基础查询容易，实时风险识别难 |
| 搜索结果 | 关键词查询并返回结构化结果 | **有条件做** | 需授权搜索来源或垂直索引，不适合自建全球搜索 |
| 天气 / 空气质量 | 查询预报、历史天气、环境数据 | **有数据方再做** | 当前缺数据供给，安装节点不会自动产生数据 |
| 体育 / 航班 / 金融行情 | 查询比分、延误、价格等动态信息 | **有数据方再做** | 核心是数据授权、覆盖和更新速度 |
| 物流追踪 | 查询运单轨迹和异常 | **有合作方再做** | 需要承运商或商家授权，不能开放任意运单查询 |
| 短信 / 邮件 / 电话通道 | 发送验证码、通知和呼叫 | **当前不适合** | 通道、送达信誉和运营成本高，项目优势不明显 |
| 支付清算 | 收付款、结算、提现 | **当前不适合** | 超出当前社区共享定位，现有开发余额不是支付系统 |

## 建议顺序

1. **先做文件处理包**：从转 PDF、合并、拆分开始，验证“一人部署、别人直接用”。
2. **再做数据来源包**：先接一两个固定来源，让不同维护者贡献不同内容。
3. **有明确需求再做地图包**：先覆盖一个区域，避免一开始维护全球数据。

**文件处理最容易起步，数据来源最能形成社区价值。** 热门不等于有竞争力；只有用户愿意反复调用、提供者愿意持续维护，才值得扩展。

## 当前还缺什么

已有服务发现、订单、传输和部分内容提取基础；新包仍需补齐**专用引擎或数据源、调用权限、运行隔离、超时取消和结果清理**。不能直接套用 LLM 包就视为完成。
