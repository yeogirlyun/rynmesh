# Gshopper 三插件统一当前账号与同步刷新
**需求稿 v3（精简版）· 2026-11-04**　取代 v2。v2 中超出本次范围的设计保留在 git 历史（77fd888）。适用于同一台设备上的 Gshopper 工作台、Gshopper Dashboard、联盟营销三个插件页面，以及 Ryn 扩展页里的公司连接卡。

## 一、目标
三个插件只有一个「当前公司账号」。无论从哪个入口登录、退出或换号，所有打开的页面一起更新：显示同一个人，用同一个人的身份取数据，用户不需要手动刷新。

用户看到的效果：
- 在任意一个插件登录后，其他已打开的页面自动显示同一个人。
- 在任意入口退出后，所有页面一起回到未登录状态。
- 从 A 换成 B 后，任何页面都不再显示 A 的名字或数据。
- 重启 Ryn 或重新打开窗口后，各页面状态一致。

「显示当前登录人的地方」包括顶栏姓名、头像菜单、账号徽标、「以我查询」的默认筛选、当前审批人和发送账号提示。联系人、历史发言人、制单人、审计记录等业务记录里的姓名保持原样。

## 二、现状：为什么会不一致
核对基线：公司插件 chat-backend develop 275b228（路径相对 `integrations/company-app`），Ryn develop 77fd888。

每个页面各自判断「当前是谁」，也各自退出：

|位置|怎么判断当前用户|怎么退出|
|---|---|---|
|公共顶栏 `web/src/main.tsx`|用 localStorage 里的 admin token 调 `/api/admin/me`；Dashboard 路由遇到 403 时再查 `/api/dashboard/session`|只注销工作台 MCP 一条连接，失败被忽略；清掉 localStorage 后提示「已退出登录」|
|联盟营销 `web/src/screens/TrackerManagementWorkbench.tsx`|页面自己保存 adminToken 和 adminUser|调用 `/api/company-plugin/oauth/logout`，插件服务没有这个路由。错误被忽略，仍提示「各插件会话已同步注销」|
|Dashboard（服务端 `server/company_plugin/dashboard_sso.py`）|插件服务向 Ryn 宿主取已验证身份，只看 company-dashboard 这一条连接的登录状态|跟随这条连接的状态|
|企微面板 `web/src/screens/CompanyFinanceApp.tsx`|跟随选中的 financeServer，或回退到工作台连接|注销所选连接，并尝试注销 company-finance provider|
|Ryn 连接卡 `webapp/src/screens/McpAuthSettings.tsx`（Ryn 仓库）|每条 MCP 连接单独显示|只退出被点的那一条|

变化通知只在同源窗口之间传递：`web/src/domain/session.ts` 的 `AUTH_CHANGE_EVENT`，以及两个 token 键的 storage 事件。宿主侧的变化，例如在 Ryn 连接卡上退出、令牌失效，插件页面收不到。组织缓存等 localStorage 数据也不按账号区分。插件服务的退出接口（`server/application.py`）会依次注销已登录的 `company-*` 连接，但失败一律忽略。

## 三、方案

### 1. 唯一来源：当前公司账号
插件服务新增一个接口（建议 `GET /api/company/account`），所有页面只从这里读取当前用户：
- **state**：未登录 / 已登录 / 切换中。
- **memberId**：最近一次成功、可验证的显式登录所确认的公司成员标识。插件服务持久保存该标识及账号版本，重启时复核。逐一核对扫码、密码和连接卡登录的身份凭据，缺少可信成员标识的入口接入统一登录动作。Dashboard 的 verified_desktop_identity 证明只适用于 Dashboard。
- **displayName**：从公司成员目录取；取不到时显示 memberId。
- **version**：账号版本。只在登录、退出、换号时变化，令牌续期不改变它。宿主现有的 `session_revision` 会随令牌续期变化，不能直接当作账号版本。
- **plugins**：工作台、Dashboard、联盟各自的状态：可用 / 需要授权 / 无权限 / 暂时不可用。

每个插件发起业务请求前，服务端核对实际使用的凭据属于当前成员。当前为 B 而连接仍属于 A 或归属未确认时，清空旧数据，显示「B 已登录，需要授权」，阻止该连接取数。

### 2. 变化时通知所有页面
- 插件服务在账号变化时推送事件（建议用 SSE），页面可见时保持订阅。
- 插件服务定时核对宿主公司连接的状态（建议每 2 秒），轮询只更新各连接状态。单条连接失效或恢复均不能改写当前账号。宿主确认的显式登录、换号或统一退出通过账号版本通知页面。
- 页面加载、恢复可见、获得焦点时，先核对 version，再显示受保护内容。
- 同源窗口之间继续用现有的 `AUTH_CHANGE_EVENT` 做即时通知。

### 3. 页面只认这一份，版本变了就重取
- 顶栏、工作台、企微面板、Dashboard、联盟页的「当前登录人」只读这个接口。
- version 变化时，清掉本页缓存的业务数据（包括 localStorage 里的组织缓存等），按新账号重新取数后再渲染。
- 业务请求带上 version。插件服务发现它和当前账号不一致时返回 409（账号已变化），前端在写入缓存或渲染前再核对发请求时的版本，即使已成功返回也丢弃过期响应。这样切换账号时不会闪出 A 的数据。
- 页面使用的 admin token 和 Dashboard token 跟签发时的账号绑定。账号变化后作废并重新获取；插件服务拒绝与当前账号不一致的 token。

### 4. 所有入口用同一个登录、退出动作
- 三个插件的顶栏、联盟页、企微面板都调用插件服务的同一个登录和退出动作。Ryn 连接卡上退出任意一条公司连接，等同于退出公司账号。
- 宿主提供统一的本机公司退出动作，插件页面与公司连接卡共用。按可信插件归属清除所有公司连接凭据（含停用项，保留停用设置），取消进行中的扫码并拒绝迟到回调。插件同步作废 admin token、Dashboard token 和账号缓存，更新账号版本并通知。
- 只有宿主确认本机凭据已清除后，才提示「已退出」。有失败就如实提示，不再出现「各插件会话已同步注销」这类未经核实的提示。
- 账号密码登录也走同一个动作：登录成功后成为当前账号并通知所有页面，界面上不能同时出现两个身份。
- Agent 调用公司工具时直接使用宿主连接，退出后自然失去访问，本次不单独改动。

## 四、不在本次范围
- 一次扫码拿到全部插件的授权（中心设备会话、多资源授权）。
- 工作台间歇变成 NeedsAuth 的根因单独排查。
- 设备名额、刷新重试协议、旧授权迁移。
- Agent 任务归属与历史隔离，以及发送、审批等有副作用操作在换号时的处理。
- 权限变化后页面即时刷新。业务接口照常按每次请求验权。
- 子陵的管理员绑定：v2 已定口径，单独实施。

## 五、验收
同时打开三个插件页面、一个独立窗口和 Ryn 连接卡。准备两个能区分的测试成员 A、B。记录使用脱敏标识。

|编号|操作|通过标准|
|---|---|---|
|01|依次以三个插件为入口，各登录一轮|所有可见页面在登录成功后 3 秒内显示同一个人，无需刷新|
|02|逐个入口各退出一轮，包括 Ryn 连接卡|所有可见页面在本机退出后 3 秒内回到未登录；迟到的扫码回调不能恢复账号；旧窗口回到前台先核对版本再显示数据；本机全部公司连接的凭据（含停用连接）已清除|
|03|A 有查询正在进行时换成 B|没有任何页面显示 A 的姓名或数据；之后的请求都以 B 的身份发出|
|04|保持登录，经过一次令牌续期|页面不刷新、不清空，显示的人不变|
|05|断网时退出|提示与实际结果一致，不出现未经核实的「已同步注销」|
|06|重启 Ryn，重新打开各窗口|各页面状态与重启前一致|
|07|工作台登录 B，Dashboard 保留 A 的有效连接，联盟暂时断网后恢复|三页当前人均为 B。Dashboard 清空 A 的数据，提示 B 需要授权，后台不得以 A 取数。联盟重连不改变当前人，只能以 B 取数或提示授权|

## 六、改动范围与交付
- **公司插件**（chat-backend `integrations/company-app`）：账号接口和推送、各页面改读账号、统一登录退出、请求携带版本。主要工作量在这里。
- **Ryn**：公司连接卡接入统一账号动作；宿主负责本机整组退出，包括停用连接和待完成登录。
- **中心**：不改。
