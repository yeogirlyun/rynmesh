# Gshopper 三插件统一登录、退出、换号与权限刷新
**需求评审修订稿 v2 · 2026-11-04**　适用产品为同一台设备、同一 Ryn 用户环境下的 Gshopper 工作台、Gshopper Dashboard、联盟营销，以及代表用户访问这三个插件的 Ryn Agent。

## 一、需求纪要
用户在三个插件中的任意一个完成一次公司登录，即可进入其有权使用的另外两个插件。任意入口退出，所有显示「当前登录人」的位置、打开的业务页和 Agent 同步退出。重新登录 B 后，姓名、权限和实际查询、操作数据的人全部变成 B。用户无需逐个连接、逐页刷新、重开对话或重新扫码。

「所有有名字的地方」包括当前操作人、头像菜单、账号徽标、默认以我查询的筛选、当前审批身份及发送账号提示。联系人、历史发言人、制单人和审计记录仍显示业务记录原有的姓名。验收以后台确认的企业和成员标识为准，同名员工也应能正确区分。

## 二、现有程序核对
核对基线为本地主程序 develop 的 954fbfb、公司插件 develop 的 275b228、中心节点 develop 的 6fbcde3。公司插件工作目录检出其他分支，本次按 develop 的已提交文件阅读。上一轮本机观察到工作台 MCP 已启用但记录为 NeedsAuth，同时 Dashboard 和联盟主连接为 ready，本机公司服务健康接口为 ready。这些是一个时点的状态。间歇故障的触发顺序仍需复现。

公司插件上述文件均位于 chat-backend 的 integrations/company-app 下。该目录是插件修改、验收与构建的唯一源码来源。两个基线仓库中的 main.tsx 和 dashboard_sso.py 已分叉。中心仓只维护中心认证、权限、资源声明及其发行职责；若中心打包依赖插件文件，使用标明公司仓提交的制品并校验来源。禁止从中心旧副本覆盖正式插件。

**两项中心能力确定缺失。** rynConfig.ts 的设备上限默认 5，可配置；rynOAuth.service.ts 实际统计每位成员未撤销且未过期的 grant，一个资源授权就占一个名额。若每台设备获三项独立授权，第二台申请第三项时会触顶。当前撤销按令牌定位单个 grant，宿主的撤销请求失败可能被忽略。遗留 grant 可占用名额直到其刷新有效期结束（默认 30 天）。授权码校验资源，刷新也要求原资源相同。目前没有将一次扫码变为同设备多资源授权的协议。

**R1 首批故障复现。** 以下两条是有源码依据的故障路径，尚未认定为用户这次掉线的现场根因。

1. 让中心完成刷新并提交轮换，再由测试代理丢弃成功响应。宿主保留旧刷新令牌，下次再用它；中心检测到重复使用会撤销对应 grant，依赖该 grant 的连接可能一起失效。对照组在请求抵达中心之前断网，区分两种超时。
2. 让两个重复连接共享一项授权，停用一个，通过活动连接轮换，使停用项留下旧凭据。模拟休眠直到访问令牌过期，重新启用旧项并让它先访问。另测停用期间发生退出和换号。核对中心撤销事件、宿主使用的授权代次及活动连接结果，不在日志中保存凭据。

## 三、实施要求与依赖顺序

### R1　先盘点入口和资源，建立可重复的故障基线
开发者先用实际安装的桌面和插件列出三张清单。① 每个账号显示、扫码、账号密码、重新登录、取消和退出控件，注明所在路由、浮层、iframe 或独立窗口。② 每个活动连接对应的插件、资源、授权范围、服务实例及用途，包括本机工作台、Dashboard 中心、联盟业务和财务连接、停用的历史重复项。③ 身份或数据寄存在哪里，包括宿主凭据、provider 会话、本地 admin 与 Dashboard 凭据、前端内存、组织及聊天缓存和 Agent 工具目录。每项列出现有读取者、失效触发者和验收用例。实机菜单与源码不同须分别记录。

先复现同时打开三页、使用到期连接、关闭重开工作台等路径。用同一次操作的关联编号串起登录回调、续期、撤销、发现工具和首个业务请求。记录错误分类、发生顺序和受影响资源。未能复现的原因保持待验证；交付时用相同路径复测。

### R2　明确谁决定当前账号，谁决定业务权限
中心认证服务确认公司成员的稳定标识和在职状态。Ryn 保存本设备当前公司会话及其版本，并向三个插件、扩展面板和 Agent 提供相同的账号快照。快照包含公司、成员、显示名、会话版本、权限版本以及各插件访问状态。界面只能据此显示当前用户。业务后端仍按该成员判定菜单、操作、记录范围及资源权限。

工作台本机服务实例凭据只证明服务实例可信；公司用户授权证明谁在访问；Windows 企微绑定决定能读哪一个本机账号。三者各自校验。资源不同要通过中心签发适用授权，禁止跨资源复制访问或刷新令牌。中心必须新增设备会话及派生资源授权。宿主用已验证的设备会话按需申请目标资源，中心逐项检查成员、设备会话、客户端、资源白名单和权限上限。页面、插件与模型均不得取得宿主刷新凭据。中心按成员和受信设备标识统计有效会话，同机同成员重新登录替换旧会话并使旧子授权失效；多资源只占一席。达到上限时提示名额已满，允许通过已验证的设备会话管理释放指定旧席位。并发登录不得突破上限。退出按本次会话编号级联失效、释放一个名额，不能用设备名追溯撤销后来建立的会话。

### R3　所有登录入口收敛到一次交互
从任意插件、顶栏或 Ryn 公司连接卡首次进入，三个入口共用一个进行中的扫码流程。重复点击或并发打开只展示同一流程。扫码成功后先确认公司成员，再获取三插件各自权限和必要授权，并刷新已打开的界面及 Agent 目录。用户可以直接从第二个插件开始工作。某个资源无权使用就显示已登录的姓名和“无访问权限”；资源暂时不可达就显示重连。

取消扫码要结束待办流程并丢弃迟到回调。首次登录取消后保持未登录。用户主动选择切换账号时，先封住旧身份和旧数据；取消后停在未登录页，明确允许重新登录。三个插件普通登录统一走企微。子陵扫码后按已核实的唯一成员绑定自动获得公司管理员角色，仍由各业务后端核定具体权限。现有本地管理员密码不能自行建立第二个公司身份或覆盖当前员工；已有密码运维流程若需保留，只能进入隔离运维入口。映射缺失、重复或成员不在职时拒绝授予管理员权限并提供可诊断原因。正式成员标识在受控配置中登记，仓库只保存脱敏验收证据。

### R4　退出、换号和离线处理
任意入口点击退出，宿主先持久记录本设备退出并递增会话版本，停止派发公司请求，取消待扫码、待续期和待审批，清除当前成员关联的三个插件凭据和页面数据，通知所有订阅方。中心撤销本设备本次登录产生的全部资源授权。重复退出应得到同一结果；其他设备和无关 MCP 保留自己的会话。

离线时也要完成本机退出。中心未确认时显示“本机已退出，联网后完成服务端注销”，持久记录待撤销的旧授权标识；重启、联网后继续，仅作用于该次旧会话。不能凭某个页面清空存储就宣布全部注销。B 登录生成新版本，A 的网络响应、回调、续期、延迟撤销或已打开的旧页面都不能覆盖 B。页面首次加载、恢复焦点、浏览器返回和应用重启时，先核对版本再展示受保护内容。

### R5　逐个刷新界面、权限和数据
|界面|退出时必须清掉|登录 B 后必须重新取得|
|---|---|---|
|公共顶栏、扩展连接卡|A 的姓名、头像、角色、已认证徽标和旧连接成功提示|B 的真实显示名及各资源状态。没有业务权限也能正确显示 B|
|工作台与企微面板|当前账号详情、组织树、联系人、已选群、消息预览、草稿的可操作状态、旧目标引用|B 的部门与可见范围、企微绑定及同步状态。若本机企微为 A，显示账号不匹配并阻止读取和发送|
|Dashboard 及嵌入财务页|旧菜单、表格、金额汇总、详情、导出入口、查询结果和待执行操作|B 的角色、可见账套或账户范围、查询与写入资格。深链接也须重新鉴权|
|联盟营销及管理页|旧管理身份、渠道、推广记录、提现列表、审批选中项及可操作按钮|B 的渠道归属、可见数据和审批权限。切换用户后直接打开旧详情也要验证记录归属|
|Agent 及任务执行|旧工具授权、待执行确认、选择的企微账号与目标、旧文件或结果的访问能力|新调用按 B 重新发现和授权。主线以保守方式关闭旧公司任务的展示、续跑和旧结果读取，要求开新公司任务；无法证明归属的旧任务按同样规则处理。逐任务精确归属及历史复用见独立项目 A1|

Dashboard 的 60 秒租约只复用已验签的远端身份。插件设计及 dashboard_sso.py 将角色和权限排除在身份凭证外；既有业务鉴权继续校验账号、权限指纹和数据范围。远端单方面撤销身份在本机尚未知时，可能到租约届满才被发现；本机主动退出或换号则立即失效。逐资源验证撤销业务权限后的下一笔请求被拒，不为此额外引入全局权限推送。页面在恢复焦点、下一次操作或收到 403 时重新取权限、目录和数据；新增权限后无需扫码。普通业务 403 不触发全组退出。

### R6　区分掉线原因，处理进行中的操作
服务短暂断开时保留已确认的公司身份，给该插件显示“正在重连”，恢复后重新发现工具。访问令牌到期时，同一授权同一时间只有一个续期者，其他连接等待并取新结果；宿主发送前持久记下当前代次与一次刷新操作编号，超时或进程重启后用同一编号重试。中心原子绑定原授权、客户端、资源和该次操作，建议初始重试窗口为 60 秒；同一窗口内只轮换一次，同一受信调用方可取回同一结果。窗口外或操作不匹配不得凭旧令牌取新凭据。窗口已过且状态不明时，停止盲重试：阶段 0 提示恢复该连接，阶段 1 用仍有效的设备会话重建资源授权。撤销优先于重放结果，禁止退出后凭重复请求恢复会话。单资源授权失效先尝试用有效公司会话修复；明确整次公司会话被撤销才同步要求重新登录。业务拒绝显示无权限，本机企微未登录、未同步、绑定不符各有独立提示。

只读请求在当前版本下可重新查询。对于发送、付款、审批等有副作用的操作，以服务端是否已受理为界。未提交的 A 操作立即失效；已受理的操作保留 A 的归属和原回执，状态不明按原操作编号核对。切换 B、服务重连或恢复任务均不能自动重发或替 B 承接审批。

### R7　旧安装迁移与发布顺序
阶段 1 启用设备计数前须完成最小迁移：为旧 grant 保留兼容路径；只有能证明同一成员、设备及授权归属时才合并计数。无法证明时提供一次扫码替换并撤销经核实属于本机的旧 grant；不得按设备显示名合并或自动挤掉其他设备。先发布可识别新旧客户端的中心认证与撤销能力，再集成宿主会话管理、插件服务和全部前端入口，最后切换正式版本。升级时对既有公司凭据向服务端核实归属：能确认同一有效成员时无感接续；出现不同成员或不能确认时统一回到一次公司登录，不能按“最近使用”挑账号。保留用户停用状态、自定义连接和无关配置。随后启用旧插件时重新取得当前账号授权。回滚须确保已退出、已撤销和已换号的旧凭据不会恢复有效。

|阶段 1 · 一次扫码与全组退出|中心设备会话、多资源授权、名额及级联撤销；宿主统一快照、会话版本与所有登录/退出入口；绑定子陵管理员；切号时旧公司任务先关闭。完成 R7 最小兼容迁移与本阶段回滚|01、02、03、06、07、12、13、14 及 11 的管理员绑定部分。三种首登顺序、真实资源调用、独立设备和自定义上限均通过，才能宣称一次扫码可用|
|阶段 2 · 业务权限与旧安装验收|三插件权限和数据范围更新、企微账号匹配、缓存清理、升级与回滚全矩阵；完成真实群读取。基础跨账号保护从阶段 1 即生效，企微尚未能验证账号时拒绝读发|04、05、08、10、11，并回归 03、07。包括用户原始的最近两天群消息任务|
|独立项目 A1 · Agent 任务归属|给公司任务、工具结果、附件引用、审批与模型上下文登记可信成员，处理旧无标识任务；支持原成员返回时恢复。跨成员读取、模型重放及已受理操作按原归属隔离|09 完整用例使用真实模型；阶段 1 的保守封锁单独验收。A1 不阻塞三插件单点登录交付|

每一阶段单独标注已完成用例、实际构建、发布顺序和可回滚版本。阶段 0 优先解除现场问题；排期由负责人完成故障复现、中心兼容评估后估算。

## 五、验收环境与矩阵

测试负责人交付可重复运行的故障注入装置和操作说明：可按指定请求暂停或释放扫码回调、在中心提交轮换后丢响应、延迟返回旧账号的成功及 401、模拟服务重启、访问令牌过期与两台独立设备。记录请求关联编号、脱敏成员、会话和资源标识、轮换次数与最终结果。03、06、12 先在隔离环境运行；真实凭据与业务数据不得进入测试产物。

09 需要接入真实模型的 Ryn 环境；10 还需要装有可用企微客户端、绑定账号且已同步测试群的机器。当前评审所述虚拟机缺真实模型，自动化夹具只作前置验证；安排在具备模型和受控企微测试群的验收机补跑，核对工具轨迹、时间范围和群内预置消息。没有实测条件的用例列为待验，不影响已独立验收的较早阶段。
准备 A、B 两个能实际区分的测试成员，安排不同的 Dashboard 数据范围与联盟权限，至少一个成员有已同步的指定企微测试群。三页、一个额外窗口、Ryn 扩展卡和 Agent 同时打开。每项记录实际账号、调用结果、界面变化及扫码次数，使用脱敏标识。

|编号|操作|通过标准|
|---|---|---|
|01|以三个插件分别作为第一次登录入口，各做一轮；另做同时点击三处|每轮只产生一个扫码流程，一次扫码后所有入口展示同一成员；三插件各做一次真实只读查询或得到预期权限拒绝|
|02|按 R1 清单逐一点击每个退出入口；随后切到旧窗口、返回旧详情并重启 Ryn|其他可见窗口自动退出，无需手动刷新。旧请求、深链接、旧 Agent 工具不能读取数据，重启仍退出|
|03|A 查询进行中切换 B，延迟 A 的查询、扫码回调、401、续期和退出结果|没有一帧旧业务数据作为 B 展示；旧成功不能恢复 A，旧失败不能踢掉 B。各页面及新请求均为 B|
|04|A、B 姓名相同；B 无财务权限但有联盟权限|能以稳定标识区分；Dashboard 保持 B 已登录并拒绝越权，联盟正常。直接 API、深链接与 Agent 结果一致|
|05|在线调整 B 的菜单、操作及记录权限，再恢复一项权限|下一次受限调用被拒；已打开列表、详情、按钮和工具可用性在恢复焦点、下次操作或 403 后更新；恢复后无需二次扫码|
|06|三插件同时触发续期；轮换期间模拟超时、插件服务重启及单资源故障|记录同一授权仅一次有效续期；其他资源持续可用。可恢复故障自动恢复，全过程零额外扫码|
|07|断网退出、重启、联网；另测中心主动撤销设备会话|本机即时退出；恢复网络后确认旧授权失效并且不误撤 B。中心主动撤销后三插件统一进入登录态提示|
|08|旧数据含冲突账号、禁用连接、重复默认连接及自定义连接，执行升级再回滚|不存在自动选错成员、复活旧授权或擅自启用连接；无关插件与其他设备可照常使用|
|09|在 A 的 Agent 对话准备发送，再切 B；分别模拟提交前和已受理但回执延迟|旧审批不能执行，历史受保护消息不进入 B 的上下文，回执仍归 A，实际发送次数不因重连增加|
|10|从工作台以外的插件扫码一次，进入 Agent，按群名查找并总结最近两天；再换成本机企微与公司账号不一致|匹配时由查找和读取工具返回该账号可见的测试消息，按约定时区核对日期；不匹配时读、发均阻断。无消息与无权限提示不同|
|11|以已绑定的子陵、同名未绑定员工和普通账号分别登录，尝试旧管理员密码入口；直接打开三个路由、iframe、后台窗口休眠再恢复|所有普通用户入口均受统一会话约束，无法利用旧本地 admin 凭据重新显示高权限姓名或数据|
|12|在原先断续的操作路径上，至少跨一次真实令牌轮换、一次宿主重启和一次断网恢复|记录公司会话、各资源状态与首笔业务请求结果，能从脱敏事件定位实际失败阶段。仅服务健康或工具列表正常不能算通过|
|13|同一成员在第一台设备依次打开三个资源，再在第二台登录；达到配置上限后并发申请新设备，再退出第一台|第一台只占一席，第二台可正常进入。超限提示明确；退出释放一席，第一台全部旧资源令牌失效，第二台可继续使用|
|14|子陵扫码后进入三个插件与 Agent，再切到同名普通成员；制造映射缺失或重复，重试旧密码入口|只有可信企业和成员标识与唯一管理员绑定相符时才获得管理员权限；顶栏、实际管理操作和审计记录一致。同名、缺失或重复映射均不能提权|
