# 企业微信聊天修复与 Agent 发送接口需求

日期：2026-11-02

状态：需求与验收约定，功能尚未完成。

目标：让企业微信聊天可以顺畅收发文本、图片和文件，历史记录稳定显示；界面和 agent 共用发送能力，agent 通过接口发送，不需要点击窗口、模拟键盘或控制电脑。

## 范围和实现原则

本轮处理以下六项。业务实现归属公司插件，主程序仅在通用插件工具接入确有需要时修改。先核对实际安装版本与源码归属，再基于对应源码修复。

复用现有账号、会话、鉴权和发送请求标识，采用最小必要的本地发送队列及状态记录。无需引入新的消息中间件、独立开放平台或另一套账号系统。后台可以依赖已登录的本机企业微信及其发送组件，但界面和 agent 都不依赖电脑操作流程。

## 1 消息发送状态明确并支持失败重试

需求：点击发送后立即在当前对话显示消息气泡，后台发送。每条消息独立显示发送中、成功或失败；失败项提供重试和简短原因，不阻塞下一条消息。重复提交同一请求不能造成重复发送。

结果暂时不明确时，后台继续核对原请求，不直接当作失败重新发送；该状态也显示在消息旁。成功表示已有可核对的发送确认，不把本地入队冒充送达。

验收：连续发送两条文本，均立即出现且不串会话；模拟一次明确失败，消息旁出现失败状态，重试后只成功发送一条。重复提交同一请求不新增消息。

## 2 历史记录稳定加载

需求：进入会话先显示已有缓存，再后台更新。短暂请求失败保留同一账号已显示的记录；首次无缓存时显示加载状态，不能把加载中画成没有聊天记录。只有明确退出或切换账号才清理对应显示。读取历史不等待完整同步结束，后台结果不能覆盖成其他会话的记录。

验收：已有记录的会话模拟一次刷新失败，记录仍在；恢复后正常更新。切换两个会话，内容不串；首次加载期间有明确加载状态。

## 3 对话滚动位置正确

需求：首次进入对话定位最新消息；本次打开期间再次进入同一对话恢复阅读位置。用户在底部时，新消息跟随到底部；用户上翻阅读时不强行拉动。历史更新和图片加载不应把当前阅读位置拉到顶部。

验收：用一个有足够消息产生滚动条的会话，检查首次进入在底部、上翻后刷新不跳动、切换回来恢复位置；底部收到新消息能看到最新内容。合并在一次浏览器流程中完成。

## 4 提交后清空输入框

需求：消息加入本地发送队列后清空本次内容，输入框立即可继续输入。失败内容保留在消息气泡中，通过重试处理；旧请求完成时不能清掉后来输入的新草稿。入队前校验失败则保留原稿。

验收：发出 A 后立即输入 B，A 的成功或失败都不影响 B；输入框不会残留已提交的 A。

## 5 图片 文件 拖拽和 Agent 接口

### 界面发送

支持图片及企微通道允许的各类普通文件，包括文档、表格、PDF、压缩包、音视频等，不只支持图片。实际大小及类型限制以接入通道为准，实施时记录真实限制，不承诺无限大小。

支持文件选择器、拖拽一个或多个文件到聊天区域，以及剪贴板粘贴图片。添加后显示待发送列表，图片显示缩略图，普通文件显示名称及大小；可以移除，点击发送后进入队列。拖拽仅添加，不直接发送。图片按图片消息发送，其他附件按文件消息发送；不支持的文件在发送前说明原因。

### Agent 接口

通过现有插件工具机制提供可发现、可调用的接口，至少具备以下能力。具体工具名和 HTTP 路径在实现时沿用项目规范，不在本需求中另建协议。

| 能力 | 必要输入及输出 |
| --- | --- |
| 查询可发送账号及会话 | 返回当前账号、发送可用状态、会话名称和稳定会话 ID，供 agent 明确选择目标 |
| 添加附件 | 接受上传文件，或服务端可访问且调用方有权读取的本地文件；返回附件 ID、名称、类型、大小 |
| 发送消息 | 指定账号、会话 ID、唯一请求 ID，提交文本或附件；返回请求 ID 和当前状态，不等待最终确认 |
| 查询结果及失败重试 | 按请求 ID 查询状态和错误原因；明确失败可重试，结果不明先核对，同一请求不能重复投递 |

界面与 agent 使用同一发送服务和状态规则，文本、图片、文件均可通过接口发送。复用现有鉴权和账号权限；目标有歧义时不能仅按显示名称猜测发送对象。工具说明提供必要参数、状态含义和一个调用示例，足够 agent 直接使用即可。

验收：文件选择器添加一张图片；一次拖拽添加两个普通文件（例如 PDF 和 ZIP），移除其中一个后发送；粘贴一张图片并确认预览。接收端能查看图片、下载保留的文件，文件名和内容正确。再由 agent 通过工具完成文本、图片、普通文件各一次发送并查询结果，全程不使用电脑控制；其中一次失败重试复用第 1 项用例。用一个超出通道限制的文件检查明确提示，不遍历所有扩展名。无有效授权的接口请求被拒绝。

## 6 发送交互及时反馈

需求：发送动作不再等待原生调用或历史数据库确认后才更新界面。常规本地环境下，文本点击发送到气泡出现、输入框清空的目标为 300 毫秒以内；文件在添加时先显示待发送项，上传或发送耗时由对应项反馈。最终送达取决于企微及网络，不承诺固定送达时间。

移除输入区长期占用的“等待服务器确认”“请勿重复发送”等全局发送提示；每条消息自行呈现状态。查询状态和历史同步不能阻塞继续输入或提交下一条。

验收：人工延迟后台响应 10 秒，文本仍及时出现、输入框可继续输入并提交第二条；状态最终能收敛。记录一次正常本机交互耗时即可，不开展性能压测或分位数统计。

## 最小验收与完成条件

采用少量定向自动化检查覆盖请求去重、失败重试和状态转换；一轮浏览器流程覆盖输入、历史、滚动、文件选择与拖拽；一轮受控真实企微收发覆盖文本、图片、普通文件及 agent 调用。真实发送仅发往明确授权的测试会话，不对业务联系人批量发送。模拟慢响应和失败使用隔离环境，不通过干扰真实企微制造故障。

相同场景共享证据，不为每条需求重复跑全套。不做全文件类型矩阵、全部历史回放、多账号大规模组合、压力测试或长期稳定性测试；仅在发现相关失败时扩大检查。编译和定向检查通过后，还需完成上述实际交互验收，不能仅用接口返回成功代替接收端确认。

功能完成后将对应修改集成到各自仓库的 develop，基于已提交源码构建。交付只记录提交号、必要验证结果和安装位置；更新前保留回滚版本，保留配置和用户数据，重启后检查版本、健康状态和插件服务。脱敏验收结论存放 docs/acceptance/，不提交凭据、聊天原文和大型产物。本需求文档提交不代表六项功能已实现或验收通过。
