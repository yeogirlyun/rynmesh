# 把我的 AI 分享给朋友：实施方案

日期：2026-09-15。状态：下一轮需求与实施计划，尚未开发或验收。本方案基于已提交的八项用户功能，独立于上一轮 95 条验收用例。

## 1. 要让用户获得什么

**一句话：朋友把配好的 AI 分享给我，我不用下载模型，也不需要高配电脑。**

- 提供者 A：已有可用的 LLM 包，愿意让指定朋友使用，随时可以关闭。
- 使用者 B：安装或打开 Ryn，接受邀请后直接聊天，不填写模型地址、API Key 或服务编号。

首个交付目标：**A 启动已有 LLM 包 → 邀请 B 使用 → B 接受并得到一次真实回答 → A 撤销后，B 的新请求被拒绝。**

B 仍需运行 Ryn 客户端，但不需要安装模型。问题会发送到 A 的设备；使用前明确显示提供者。A 必须在线、模型就绪且允许访问，不能承诺随时可用。

## 2. 现在已有什么，需要补什么

以下为对当前代码的核对，不把已有能力重复列为新开发。

| 能力 | 当前已有 | 本轮增量 |
|---|---|---|
| LLM 包和运行时 | 模型配置、安装、启动、就绪检查、自检、停止和恢复 | 在可用模型旁提供清楚的“分享我的 AI”入口；复用用户已有包 |
| 好友关系 | 创建邀请、二维码、审核、接受、过期和撤销 | 新增明确表示“邀请使用这个 AI”的邀请用途 |
| 好友 AI 权限 | 指定好友和服务授权、权限修订、撤销及服务端检查 | 把授权接进分享流程，显示等待接受、已授权或未完成 |
| 好友服务发现 | 刷新授权服务，显示就绪、忙碌、失效等状态 | 接受后自动发现本次获准服务，避免用户手动寻找 |
| Ask Ryn | 已有指定好友 AI 的聊天链接、历史和真实问答 | 完成接受后直接进入指定服务的聊天页，并保留清晰的返回/恢复入口 |

当前 `FriendAI` 已有 “Ask 某位好友的 AI” 链接。因此“选好模型后打开聊天”主要复用现有能力；真正的新工作是邀请与授权衔接、入口整理和安装后的接续体验。

## 3. 用户怎么操作

### A：分享自己的 AI

1. 在 Services → Manage 查看已有 LLM 包。未配置时进入现有设置流程；配置好后启动并确认真实就绪。
2. 点击 **分享我的 AI**，看到模型名称、当前状态、使用费用和“问题会在我的设备处理”的说明。
3. 选择一种方式：
   - **已有好友：**选择 B，确认只允许 B 使用当前服务。
   - **邀请新朋友：**创建单人、一次性 AI 邀请，提供复制和二维码。
4. 查看结果：等待接受、授权处理中、已允许使用；能够取消未使用的邀请、撤销某位朋友或暂停全部共享。

第一版针对当前配置的一个 AI 服务，不扩展同时托管多个模型。创建邀请不分发模型文件、运行时或 A 的凭证。

### B：接受并提问

1. 收到邀请，看到“谁邀请我使用哪个 AI”。
2. 已安装：打开应用进入该邀请的审核页。未安装：到对应平台的真实下载入口，安装后继续这份邀请。
3. 审核页显示提供者身份、模型、费用、有效期和内容接收方。点击 **接受并开始聊天**。
4. 应用确认好友关系和该服务授权，再刷新服务状态，自动进入 Ask Ryn，选中 A 的服务。
5. B 输入自己的问题并发送，得到真实回答。聊天页持续显示“正在使用 A 提供的模型”。

“自动进入聊天”不自动发送示例问题，也不携带其他会话历史。邀请失效时留在恢复页面，不跳到一个看似可用的空聊天窗口。

安装接续优先复用现有应用链接；打不开时保留 **复制邀请 → 安装后粘贴继续** 的明确兜底。未实现自动接续的平台不能写成“一键直达”；没有普通用户安装包的平台需如实说明，不能把开发命令当成无门槛安装。

## 4. 开发怎么完成

### 第一步：收拢已有好友的分享入口

在模型管理页增加“分享我的 AI”，复用现有好友选择、发布确认、授权和 Ask 链接。授权之后让 B 从好友 AI 卡片直接进入对应聊天。先实际走一遍现有流程，只补缺失的入口、提示和状态联动。

**本步交付：两位已经是好友的用户，不填服务参数就能分享 AI 并完成真实问答。**

### 第二步：接通 AI 专用邀请

为邀请增加可验证的用途与服务绑定，包括邀请编号、提供者、服务标识、展示信息、有效期和使用状态。具体接口命名在实现时沿用现有模块规范。

- 普通加好友邀请保持原来的含义，不自动增加 AI 权限。
- A 创建 AI 邀请时明确同意：首位成功接受这份邀请的人获得指定服务权限。界面说明不要公开转发；默认沿用 15 分钟有效期，可取消、只可用一次。
- B 审核后接受，服务端绑定 B 的实际身份。重复接受返回同一结果，其他身份不能再次领取。
- 好友关系和 AI 授权分属不同存储，不能仅在前端连续调用两个接口就显示成功。使用持久操作编号记录进度；部分失败可继续，重启或响应丢失后查询原操作，不能多建关系或扩大权限。
- A 取消邀请、撤权或删除关系后，旧的未完成操作不能重新授予权限。完成前重新核对取消状态、关系和授权修订。
- 接受时重新确认实际服务、价格和状态；服务已更换或价格变化时要求重新审核，不静默接受邀请里的旧信息。

**本步交付：A 邀请尚未成为好友的 B，B 接受后自动完成限定授权并进入正确的聊天页。**

### 第三步：补安装接续并交给真实用户试用

整理邀请说明、已安装/未安装入口、接续失败兜底及平台支持说明。让一个无本地模型的新用户从收到邀请开始走完整流程，记录卡在哪一步。

普通安装交付是本步前置：当前本机试用候选仍是 Python wheel＋浏览器。若面向普通 Windows 用户首发，需交付普通安装器；若选用已有 macOS 安装器，需有相应设备验证接续。前置未满足时，本步与 FAI05 保持未完成，第一、二步仍可在已安装客户端之间试用。

邀请能力不放进页面统计或访问日志。需要经网页跳转时，接续信息不能使用会上传给网站的普通查询参数；只传递必要信息，完成或取消后清除临时接续记录。

**本步交付：在明确支持的平台上，B 能根据页面说明自行安装或打开应用，继续原邀请并完成问答。**

三个步骤分别提交小 PR；第一、二步可以先在已经安装客户端的用户之间试用，第三步完成后再对外宣传安装后的完整接续体验。

## 5. 异常时应该显示什么

| 情况 | 用户看到的结果和操作 |
|---|---|
| A 在线，但模型未启动或未就绪 | “朋友的 AI 还没准备好”，保留输入，提供刷新；A 有启动或检查配置入口 |
| 模型忙碌 | “朋友的 AI 正在处理其他请求”，允许等待或手动重试；不显示离线 |
| A 离线或连接不可达 | 说明暂时无法连接，保留草稿；不自动切换其他提供者 |
| 邀请过期、取消或已被别人使用 | 不建立新的授权；告诉 B 向 A 获取新邀请 |
| 已是好友，但授权未完成 | 显示具体未完成阶段，继续原操作；不要求重复加好友 |
| 费用未知或发生变化 | 不显示免费；发送前重新确认实际收费信息 |
| A 撤销 B 的权限 | B 的新请求被拒绝，历史仍可读；已运行任务按实际取消结果显示 |
| 问答超时或应用重启 | 查原任务状态再继续，不能自动重复提交或重复结算 |

费用沿用已有服务规则；开发用 Task Balance 不能描述成人民币收费。首轮试用建议由 A 明确配置零价服务，实际价格确认是零后才显示免费。本轮不增加支付、套餐、自动扣费或收益结算系统。

## 6. 验收标准

这是新流程的用例，不重新扩大上一轮基础设施验收范围。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| FAI01 | A 使用已有 LLM 包启动、自检 | 显示实际模型与就绪状态；复用现有包，不另建推理实现 |
| FAI02 | A 分享给已有好友 B | 确认具体好友和服务；B 可直接打开该服务聊天，无需填写地址或编号 |
| FAI03 | A 创建邀请，陌生于 A 的 B 接受 | B 审核提供者/模型/费用；关系与限定授权实际生效后进入指定 Ask 会话 |
| FAI04 | B 不安装模型、不配置 API Key，发送问题 | A 的真实模型返回答案；B 没有下载模型文件或调用预置假回答 |
| FAI05 | B 未安装客户端，从邀请完成安装并继续 | 在声明支持的平台上可回到原邀请；自动接续失败有有效兜底，不丢失操作目标 |
| FAI06 | 邀请过期、取消、重放或被其他身份使用 | 不产生额外授权；同一 B 的原操作重试不重复创建关系 |
| FAI07 | 接受过程断开、部分写入失败或重启 | 恢复原操作；界面只在关系与授权均确认后显示完成；取消/撤权不被重试覆盖 |
| FAI08 | A 离线、模型未就绪或忙碌 | B 看到对应状态、保留输入且可恢复；不偷偷改用其他 AI |
| FAI09 | A 撤销 B，再请求；C 从未获授权也请求 | 两者新请求均由 Provider 拒绝；执行中任务不假报取消成功，不重复结算 |
| FAI10 | 模型或价格改变、再打开旧会话/邀请 | 要求核对实际服务与价格；旧会话仍绑定原服务，不自动转发历史 |
| FAI11 | 重启双方后继续使用 | 有效授权仍可恢复；撤销的权限不复活；历史可读 |
| FAI12 | 仅用键盘完成分享、审核、提问和撤销 | 主要流程可完成，确认和错误焦点正确，成功/失败有文字说明 |

主流程需要真实页面与真实模型；异常分支可复用已有自动化并补新增缺口，明确记录模拟部分。先在已验证的可达环境完成两节点闭环。若要宣传异地朋友开箱可用，需另补真实跨网邀请与问答证据；上一轮跳过公网不等于本轮已经证明跨网可用。

完成条件：上述首版用例有对应证据，代码已进入可安装候选，A→B 的完整路径能由用户操作完成。不能仅凭授权 API 或组件测试通过就宣称整个邀请体验完成。

## 7. 首轮用户试用与范围

先找 3 位愿意分享已有 AI 的提供者，每人邀请 1–2 位朋友，观察：邀请是否被接受、第一次问答卡在哪里、一周内是否再次使用。记录首次接受至发送/收到答案的用时，区分操作时间、连接等待和实际推理时间；不把模型速度当成固定安装体验承诺。

以上是试用计划，没有现成转化率或留存数据。默认使用本地记录和用户主动反馈，不新增集中行为采集。

首版不做公开模型市场、陌生人自动匹配、自动选择其他提供者、多模型并发、商业收费、GPU 调度改造或新的流式推理。后续可接入朋友分享的文章，让 B 对收到的内容直接提问。
