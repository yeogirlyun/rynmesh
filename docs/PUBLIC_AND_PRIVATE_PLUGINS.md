# Ryn 公开插件与私有插件：安装、更新和发布说明

日期：2026-11-17。

这次把“做图”从 Ryn 主程序内置功能拆成独立公开插件。插件代码、版本、安装包可以独立维护。Gshopper 工作台、Dashboard、联盟营销仍是私有插件，不进入公开目录，也不改用公开更新地址。

## 1. 先分清三个东西

| 名称 | 用来做什么 | 以做图为例 |
| --- | --- | --- |
| 插件 | 用户安装和管理的完整功能 | 页面、做图队列、作品管理、分享页面 |
| MCP | AI 调用工具的协议 | 不是所有有页面的插件都必须是 MCP 服务 |
| 开放的页面 | 使用某台电脑已经开放的服务 | 同事在自己的 Ryn 打开“子陵的电脑 · 做图” |

本次做图插件以页面方式提供服务，复用 Ryn 的本机 Codex 出图能力和节点页面通道。没有额外注册一个独立 MCP 服务器；Ryn 原有的 AI 出图工具保持原来的入口。以后需要让 AI 调用这套作品队列，可以在同一插件里增加 MCP 接口，不需要另建一套插件商店。

“公开插件”表示安装包可公开获取，不表示你的作品、登录账号、做图额度或电脑上的服务公开。默认安装后仅供本机使用，对外分享需要你单独开启。

## 2. Git 放在哪里

### 公开做图插件

仓库：[老板的公开 rynmesh 仓库](https://github.com/yeogirlyun/rynmesh)。统一集成分支为 `develop`。

| 内容 | 仓库位置 | 作用 |
| --- | --- | --- |
| 做图插件源码 | `plugins/image-studio/ryn_image_studio/` | 做图页面、队列、作品与后台逻辑 |
| 插件说明清单 | `plugins/image-studio/plugin.json` | 名称、版本、入口、权限、更新说明 |
| 公开目录 | `plugins/catalog.json` | Ryn 从这里知道公开插件及最新版本；含签名 |
| 插件运行管理 | `rynmesh/public_plugins/` | 主程序负责下载校验、启停、更新与回退 |
| 构建发布脚本 | `scripts/build_public_plugin.py` | 从已提交源码生成独立 ZIP 和签名目录 |
| 这份说明 | `docs/PUBLIC_AND_PRIVATE_PLUGINS.md` | 面向使用者与维护者的说明 |

安装包不放进 Git 源码目录，放在 GitHub Releases。例如：

- 发布标签：`plugin-image-studio-v1.0.0`。
- 安装包名：`image-studio-1.0.0.zip`。
- [做图 1.0.0 发布页](https://github.com/yeogirlyun/rynmesh/releases/tag/plugin-image-studio-v1.0.0)。

它与 Ryn 主程序的版本号分开。更新做图页面或队列通常只发布做图插件；只有改变主程序插件接口时，才需要先升级 Ryn。

### 私有 Gshopper 插件

继续放在[老板的私有 gshopper-ryn-node 仓库](https://github.com/yeogirlyun/gshopper-ryn-node)，以 `develop` 集成。

公司工作台、Dashboard、联盟营销继续使用已有的私有安装包和带登录鉴权的公司更新服务。源码权限、安装权限和业务账号权限分别控制。

**不要把私有插件源码、私有更新令牌、公司安装包或内部地址复制到公开 `plugins/catalog.json`。** 有人知道私有更新地址，也不应该因此获得下载和业务访问权限。

## 3. 普通用户怎么找到新插件

前提：Ryn 主程序已经升级到包含这次“公开插件管理”的构建。旧版 Ryn 不会因为 Git 多了一个文件就自动出现新按钮。

1. 打开 Ryn 的“插件”页，地址为 `/settings/plugins`。
2. 切到“发现”页签。
3. 在“公开插件”区域点“刷新目录 / 检查更新”。
4. 找到“做图”卡片，查看介绍和版本，点“安装”。
5. 确认它会在本机运行插件代码、调用本机 Codex 并保存图片。
6. 安装完成后切到“已安装”，点击“打开”。

“刷新目录”只获取目录和版本信息，不会自动把所有新插件装上。打开插件页首先读取本机缓存；联网刷新失败时保留上次可用目录，并显示错误。

新发布者把一个文件夹推到 Git，还不等于上架。必须先上传安装包，再把对应插件加入签名公开目录，用户刷新后才会看到。

## 4. 做图插件安装后怎么用

### 自己用

在“已安装”的做图卡片点“打开”。顶部会显示“在我的电脑上运行”。

本机需要安装并登录 Codex；做图插件不会附带其他人的账号、密钥或额度。页面会提示出图环境是否就绪。输入描述、尺寸和可选参考图后提交，任务进入本机队列，作品留在本机数据目录。

### 开放给别人用

在做图卡片点“管理任务与分享”，进入现有的“我的做图服务”页面，开启分享并选择范围。对方通过“开放的页面”找到你的电脑和做图页面。

| 场景 | 要不要安装做图插件 | 在哪里出图 | 使用谁的账号 |
| --- | --- | --- | --- |
| 在自己电脑做图 | 要 | 自己电脑 | 自己的 Codex |
| 打开别人分享的做图页面 | 不需要在访问方安装 | 分享者电脑 | 分享者的 Codex |
| 自己也要提供做图服务 | 要 | 自己电脑 | 自己的 Codex |

当前节点网页分享沿用已有公司通道及发布者权限。**公开安装不依赖 Gshopper，但跨电脑分享仍有当前通道的授权要求。** 本次没有新增向全网匿名开放、任意好友分享或无需授权访问的能力。提供方电脑离线或插件停用时，其他人不能继续使用它的做图服务。

## 5. 用户怎么看插件更新

在“插件 → 已安装 → 公开插件”，点击“刷新目录 / 检查更新”。

卡片同时显示：

- 已安装版本，例如 `1.0.0`。
- 目录中的最新版本，例如 `1.0.1`。
- 有新版本时显示“有新版本可更新”和“更新”按钮。
- “更新说明与来源”中说明这次改了什么，以及公开来源。

点“更新”后，Ryn 下载固定版本的发布包，检查发布签名和文件完整性，再切换运行版本。安装和更新不是执行 `git pull`，也不会运行尚未发布的 `develop` 代码。

第一版公开做图插件采用**手动检查、手动更新**。不自动安装新插件，不在后台悄悄替换做图版本。已有其他插件的自动更新设置保持原样。

### 更新时有任务怎么办

队列里有等待或执行中的任务时，更新、停用和卸载会提示忙碌。先等待任务完成，或去“管理任务与分享”取消任务，再操作。这样不会把正在出图的任务切到另一个版本。

### 更新失败怎么办

- 下载失败或文件校验失败：不切换原版本，可以稍后重试。
- 新版本启动失败：尝试恢复原来的运行版本，显示失败状态。
- 更新成功后发现问题：卡片有“回退上一版”按钮。
- 回退保留现有作品和配置；未来如果插件引入不兼容的数据格式变化，发布者必须先提供迁移与回退方案。

## 6. 私有插件怎么安装、怎么更新

私有插件不出现在“发现 → 公开插件”里。未安装它的人不会从公开目录看到 Gshopper 内部条目。

使用者从公司授权渠道取得现有公司安装包，或在支持的导入入口导入私有插件包。像 Gshopper 这样包含本地后台服务的插件，应使用配套公司安装包；单独导入网页清单不能代替安装后台服务。

已有的私有更新源跟随公司插件安装配置。之后在 Ryn 的“设置 → 软件更新”中查看公司插件服务的更新状态、检查或应用更新，仍按现有公司登录鉴权下载。

若是其他支持 HTTPS 订阅的私有网页插件，则在其更新设置中配置自己的私有地址及发布公钥；需要凭据时使用现有私有通道。不能把任意 HTTPS 地址当成无需验证的代码来源。

| 问题 | 公开做图 | 私有 Gshopper |
| --- | --- | --- |
| 谁能在公共目录看到 | 所有人 | 不进入公共目录 |
| 首次安装从哪里来 | 公开目录 → GitHub Release | 公司提供的私有安装渠道 |
| 更新从哪里来 | 签名公开目录指定的 GitHub Release | 已配置的私有公司更新地址 |
| 是否使用公司登录下载 | 不使用 | 按私有更新服务鉴权 |
| 是否共享安装状态 | 各人自己安装管理 | 各人自己安装管理 |
| 是否自动获得别人的账号 | 不会 | 不会，仍须业务授权 |

公开插件和私有插件可以安装在同一个 Ryn 中，但它们的目录、下载凭据和更新来源不混用。

## 7. 旧版做图数据怎么办

旧版数据位置继续保留：`<Ryn 数据目录>/image-studio/`。包括作品文件和 `studio.db`。独立插件继续读这个目录，不把个人数据搬进 Git。

升级到支持独立插件的主程序后，旧的内置做图服务不再自动启动；需要从插件页安装做图。插件页会提示检测到旧作品。首次迁移会关闭旧分享开关，原有分享范围和作品保留，安装后由本人重新开启分享。

停用或卸载独立插件不会删除作品。卸载会关闭分享；重新安装后可继续使用作品，再按需开启分享。普通版本更新保留已有分享开关和范围。

## 8. 维护者怎么发布下一版

1. 在任务分支修改 `plugins/image-studio/`，更新 `plugin.json` 中的版本和更新说明。
2. 测试本机做图、既有作品读取、队列、访问隔离，以及安装、更新和回退。
3. 将完成的改动合并到 `develop`，提交后从干净的 `develop` 构建。
4. 用仓库外的发布私钥运行 `scripts/build_public_plugin.py`，输出到仓库外。脚本生成 ZIP、SHA-256 文件清单和签名目录，记录源码提交。
5. 在老板公开仓库创建独立插件 Release，例如 `plugin-image-studio-v1.0.1`，上传 ZIP。插件 Release 不设为主程序的 latest，以免干扰 Ryn 主程序更新。
6. 确认包可下载且校验通过，再将生成的 `catalog.json` 更新到 `plugins/catalog.json`，提交到 `develop` 并推送。
7. 用户刷新公开目录后看到新版本。新用户可安装；老用户显示“更新”。

构建命令示例（Python 环境需已具备项目依赖）：

```powershell
python -m scripts.build_public_plugin --package plugins/image-studio --key C:/secure/public-plugins.ed25519 --output D:/release-output/image-studio-1.0.1
```

示例路径不是要求把私钥放在该位置。发布私钥必须保存在仓库外；主程序只携带发布公钥。维护者应另行安全备份私钥，丢失后不能用任意新钥匙替换而不更新客户端信任。

安装包、目录和对应源码提交是一组发布记录。已经发布的版本不要覆盖重传；修复时增加版本号。公开目录仅登记已实际上传且通过验证的发布包。

## 9. 这版范围

已设计并实现的路径是：公开目录、独立做图包、本机启停、版本检查、手动更新、回退、旧数据保留、本机页面和既有节点分享。

主程序提供运行接口版本 `host_api = 1`。不支持该接口的旧版主程序需要先升级。第一版只信任主程序内置发布公钥签发的第一方插件，不提供任意第三方 Python 代码市场或无审核自动执行。

具体发布提交、安装包哈希和验证结果见 `docs/acceptance/public-image-plugin-20261117.md`。是否已经替换某台电脑上的 Ryn，以该验收记录为准，不能仅凭 Git 已推送就认为所有人的客户端都已升级。
