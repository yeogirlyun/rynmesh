# Ryn 模型池、Agent 与无状态分享设计

日期：2026-10-09。状态：需求澄清、UI 原型及源码研究；未修改业务功能。承接 [系统 Agent v2](ryn-system-agent-v2.md)。

## 用户明确要求

1. Ryn 配置多个 AI 来源。自己调用时通过 Ryn Agent 保留任务、对话、记忆与工具状态。分享给其他节点时提供无状态推理，不运行提供方自己的 Agent。
2. 来源中的模型汇入一个模型池。用户选择其中的模型接入 Ryn Agent；池中每个模型分别决定是否允许其他节点调用。默认主控选择和分享授权完全独立。
3. 模型配置参考 ZCode 的供应商/连接/模型层次。UI 必须清楚显示这些关系及状态。

模型自身不因使用方式改变权重或获得永久记忆。有状态的是 Ryn Agent 的执行环境；单次模型请求按需携带上下文。远端调用者也可在其节点运行自己的 Agent，模型提供方仍无状态地处理每次请求。

## 两条调用路径

自己使用：用户目标 → 本机 Agent（会话、计划、权限、工具、结果）→ 选中的模型 → 返回工具调用 → 本机受控执行 → 核验 → 下一轮。

分享调用：远端请求 → 认证及模型级授权 → 使用本机保管的上游凭据调用模型 → 返回推理结果。请求里的历史和工具描述属于调用者；不注入提供方的会话、记忆、Skills、文件或工具。不在提供方执行调用者指定的函数。持续到下一次请求的会话状态由调用者负责。

“直接转过去”包括必要的协议适配、鉴权、限额、取消及错误映射，不是未经检查的任意地址转发。无状态不等于无流式连接、不记录用量或上游零日志；不承诺模型厂商的数据保留政策。

## 配置模型

| 对象 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 连接 Source | 类型、协议、地址、凭据引用、启用状态 | 不自动授权全部模型给其他节点 |
| 池中模型 Model | source_id + model_id、显示名、能力、上下文、输出参数 | 不携带用户 Agent 会话 |
| Agent 设置 | 新任务默认模型、工具范围、预算与偏好 | 不自动开启分享 |
| Agent 会话 | 本任务模型、历史、步骤、执行记录、授权 | 不成为对外分享 API 的会话 |
| 分享规则 | model_id、节点范围、并发/配额、启停、版本 | 不授予文件或设备工具权限 |

同名模型来自不同供应商时保留不同身份；权限绑定稳定模型记录，不用显示名匹配。协议、地址或模型变更后，工具能力探测失效，不能沿用旧的“已验证”。

导入时探测模型列表，接口不支持发现时可手填。连接测试、模型存在性、工具调用能力三个状态分开。列表拿到的模型不代表都有调用权限，单模型能力也不能只根据名称猜测。

所有池中模型都有分享状态；若某来源暂不支持分享，应在该行显示不可用和具体原因，不静默隐藏。同样，未通过工具调用探测的模型留在池中，但不能选为 Agent 主控。分享能力与 Agent 工具能力是两项检查。

## UI 与标注

原型采用四个页面，同一套演示状态相互关联：

| 页面 | 重点控件 | 标注 |
| --- | --- | --- |
| 模型池 | 新任务默认主控、模型列表、每行分享开关、设置 | ① 统一池和双用途；② 主控选择；③ 逐模型分享 |
| 连接配置 | 左侧来源，右侧协议/地址/凭据、连接测试、发现/手填模型、模型参数 | ④ 一条连接可包含多个模型 |
| 共享访问 | 远端请求路径、逐模型允许节点、无状态边界 | ⑤ 不共享自己的 Agent 状态与工具 |
| 智能助手 | 当前任务模型、步骤、访问范围、回执、执行节点 | ⑥ 由 Ryn 保存任务状态 |

默认主控是单选，分享是多选；两者不可做成互斥开关。一个模型可以同时是主控且分享。未选为默认的模型仍可用于某个任务或单独分享。

正式实现必须区分“全局默认”和“当前会话”：默认改变仅影响新任务；会话保持自己的模型。运行中切换应在工具调用成对结束的检查点生效，并提示新接收方；保留任务目标、步骤和资源引用，重建该协议下的模型上下文。能力不兼容时说明阻塞原因，不能丢任务或自动换来源。

新增来源或模型默认不分享；开启分享后选择节点并保存。关闭分享即阻止新请求，进行中的请求单独显示取消/完成状态。变更只作用于对应模型，不影响自己的 Agent 或同来源其他模型。

模型配置高级项包括：显示名、上游 ID、上下文窗口、最大输出、协议支持的思考参数、工具/图像能力及验证时间。原型以部分字段展示层次；其中所有模型、规格、连接测试、能力结果和任务回执都是示例。

## 原型检查范围

原型无网络请求，不读取或保存真实密钥，不开启实际分享，不调用真实模型，也不创建文件。UI 中的“测试”“执行”“保存”均明确标为演示。

浏览器验证重点：主控单选；分享独立；未选节点不能开启分享；工具待验证的模型保留在池中；新增模型默认不分享；任务模型和默认选择分开。桌面及窄屏布局另做可视检查。

## 如何把源码转化为好用的 Ryn Agent

第一优先：复用成熟机制的结构与测试思路，包括工具调度、上下文压缩、会话事件和权限分类；选择实际适合的源码片段时记录来源及许可证。ZCode 的 TypeScript 运行时与 Ryn 的 Python 节点存在语言和生命周期差异，不宣称可直接复制一个类就工作。

Ryn 必须自己完成：统一模型池、同源多模型、网盘工具、节点身份授权、无状态分享隔离、业务级幂等与结果核验、自己的 UI 和桌面打包。

引擎路线在 v2 的独立业务控制层基础上，先做技术验证：同一组 Ryn 工具与同一组任务，测试成熟运行时适配及原生最小执行循环。比较工具边界、协议兼容、任务恢复、延迟、打包体积和维护成本，再决定是否把某个开源核心作为独立进程嵌入。此验证是后续开发建议，本次未实施。

“很好用”的验收必须包含用户完整任务，而不只测试能否返回 JSON：查多份资料并生成文件；中途更正后继续；错误可恢复；长任务压缩后不忘约束；重启后不重复写；关闭分享后远端不可调用且本机仍可用；A 节点调用绝不混入 B 节点历史。

复用源码能减少摸索，不能替代强工具模型、业务工具覆盖和真实多节点测试。当前没有任何“八成效果”实测结果；只可判断已有足够公开材料支撑开发和验证。
