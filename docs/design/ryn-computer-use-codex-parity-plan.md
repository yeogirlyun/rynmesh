# Ryn 电脑控制对齐 Codex 实施方案

2026-10-19。设计与验收由 Codex 负责，代码开发由本机 Antigravity 的 Gemini 4 Argon Medium 执行。16:06（香港时间）已开始实施，独立验收尚未完成。过程记录位于 `work/computer-use-parity-20261019`。

目标是在当前 Windows 电脑控制范围内，逐项实现并验证 Codex 的工具契约、操作流程和可观察行为，包括实际模型视觉与宿主运行时。交付必须给出能力对照表和真实应用结果；“插件已导入”“工具能列出”“截图已保存”均不能单独代表可用。

对标基线为已安装的 Computer Use 26.1013.40934、Sky 0.7.8 和已取证原生 helper 哈希，见[REA 诊断](ryn-computer-use-rea-analysis-20261019.md)。私有源码逐行一致、任意模型产生相同决策及未来 Codex 版本永久一致不属于可承诺范围。任何尚未对齐的基线能力必须公开列出，不能静默删减后宣称完整对齐。其他系统及与电脑控制无关的 Codex 功能单列后续范围。

## 交付架构

采用 Ryn 自带的原生电脑控制 worker，推荐先用现有 Rust 工具链验证 Win32、UIAutomation、窗口截图和安装包集成，再确定实现细节。所有桌面操作共用一个执行核心：现有电脑工具、MCP 和新增的 Sky 兼容接口都调用它。

执行链为：插件和 Skill → Ryn 工具与持久 JS 运行时 → 会话及审批协调器 → 原生 worker → 桌面。

观察链为：原生窗口状态及像素 → 验证后的图像与快照 → 界面展示及模型图像输入 → 下一步动作 → 更新观察。图像进入所选模型的实际请求是单独的验收条件。[OpenAI 电脑控制指南](https://developers.openai.com/api/docs/guides/tools-computer-use)也要求应用执行动作、返回更新截图，并核验应用结果；该公开指南不替代本项目对 Codex 桌面实现的取证。

Ryn 应独立安装和运行这套能力。直接复用 Codex 已安装包的独立调用契约、宿主依赖和分发条件可做选型验证，但复制一个 exe 不构成完整集成，也不作为可交付方案的前提。

## 阶段零 冻结完整能力基线

复用现有 REA 证据，补查与行为对照仍不明确的窗口缓存、截图坐标、各输入入口、停止及宿主回调。静态推断和真实运行结果分别记录。

基线至少包含：

| 能力 | 必须对齐的内容 |
| --- | --- |
| 应用与窗口 | list_apps、launch_app、list_windows、get_window、activate_window，窗口身份及重建处理 |
| 观察 | get_window_state，窗口、截图、几何信息、UIA 树、实际焦点、选中内容和可读文本 |
| 输入 | 单击、双击、鼠标按钮、元素点击、输入、设值、快捷键、滚动、拖拽及相关控件动作 |
| 状态约束 | 截图与元素属于当前窗口和观察，坐标变换、DPI、多屏、移动与遮挡处理 |
| 运行时 | 持久 JS 会话、Sky 接口兼容、图片输出、任务结束与中断清理 |
| 可靠性 | 持久会话、并发初始化、撤权、超时、取消、断连、重启、结果未知与诊断 |

产出是逐项标记已证、待证、已实现、已验收的矩阵，以及固定对照用例和性能测量方式。不能用同名方法推定语义相同，也不能将提议的 Ryn 内部字段说成 Codex 已证机制。

## 阶段一 修复通信与诊断

修复已复现的同 key 并发首连竞争，采用单次连接协调或发布时保留有效赢家，避免后完成的候选关闭正在执行的会话。继续以任务、server instance、配置代次及 schema 绑定正确会话。

在写入异常路径保留经过过滤的错误码、异常类型、执行阶段和请求及会话关联。dispatched 后缺少可靠完成证据时仍为 unknown，不自动重放；有错误码不代表动作没有副作用。

验收门槛：既有两组缺陷探针转为回归，覆盖并发首连、初始化中撤权、RPC 错误、断线、进程退出、同任务读写连续性和不同任务隔离。缓存赢家不会因另一初始化被关闭；错误可定位，实际动作不重复。

## 阶段二 实现统一原生执行核心

窗口身份绑定 HWND、PID、进程启动标识和观察代次。应用发现与启动直接由该核心提供，无需依靠模型拼接启动脚本。窗口关闭、重建或句柄复用后，旧身份必须失效。

依据已取证的 Codex 行为实现有期限的聚焦恢复：窗口恢复、目标关系检查、必要的线程输入关联、置顶及焦点设置、实际前台校验，以及受控恢复步骤。所有线程关联和按键状态必须在异常、超时与取消时清理；失败后不得继续向不确定目标输入。不能简单把 20 次盲重试替代完整聚焦策略。

UIA 直接调用原生接口，提供当前焦点与明确的元素快照；截图采用可验证的窗口采集方案，区分成功图像、不可用、最小化和受限画面，避免仅以屏幕矩形采集成功就认定目标画面正确。

同一物理桌面由统一协调器串行化输入。不同任务的观察与句柄不能混用；其他任务或用户操作改变相关状态后，旧观察须重验。MCP、旧电脑工具和 Sky 门面都委托这一核心，逐步收敛现有 Python / PowerShell 动作路径。

验收门槛：启动与重新发现、前台和后台窗口、最小化、弹窗、不同应用争抢焦点、窗口重建、取消、关闭及 helper 回收均使用受控窗口验证。所有输入前都能确认正确目标。

## 阶段三 统一截图状态和输入校验

设计 Ryn 内部观察凭据，关联 task、窗口身份、截图哈希及尺寸、原点、DPI 变换、UIA 元素表和观察代次。它是 Ryn 的实现设计，不声称 Codex 使用同名 stateToken。

坐标输入以窗口相对坐标为契约，转换到实际输入坐标后，结合 WindowFromPoint、窗口关系和进程身份检查实际命中目标。窗口移动、缩放、重建、遮挡或观察失效时先重新观察。元素动作也必须验证元素所属窗口及当前快照。

中文输入、组合键、点击、滚动、拖拽和 UIA invoke / set_value 共享授权、取消及预检入口。动作完成后通过新观察核验效果；发送了输入事件不能直接当成业务成功。

验收门槛：多屏、负坐标、不同缩放、窗口移动、遮挡、弹窗、过期截图、过期元素、句柄复用、中文及快捷键。错误窗口输入和跨任务快照使用必须为零。

## 阶段四 打通模型视觉和 Skill 宿主运行时

按“模型和接入路由”声明图像能力。分别验证 Codex CLI、Antigravity CLI 和 API 适配器；模型本身支持视觉不等于当前桥接实现能够传图。现有 Codex CLI 图像载体代码可作为接入候选，仍须完成真实验证。Antigravity 当前文本桥接需要单独补充图像承载，不能直接删除检查后宣称支持。

对支持的路由，把经过验证的截图像素送入实际模型请求，关联请求 ID 与图像哈希，再接收动作决策。默认由用户选定且经验证支持视觉的模型完成观察和决策；独立视觉模型只作为显式配置的路线，不静默切换账号、模型或付费 API。

补齐运行 Codex 电脑控制 Skill 所需的宿主能力：

- Ryn 自带的持久 JS 会话和任务级会话隔离。
- `@oai/sky` 已取证接口的兼容门面，转发到 Ryn 原生核心，并清楚标明由 Ryn 实现。
- 对应的文字输出、图片输出、观察返回及 turn_ended / 中断清理。
- JS 内的每个桌面动作仍经过 Ryn 的权限、审批、取消和持久化协调；审批等待时挂起、继续同一执行，不能重跑整段脚本制造重复动作。

JS 包别名兼容不能代替整个宿主实现。其他 Skill 所需的额外依赖需逐项声明，不能借电脑控制兼容承诺任意插件都能运行。

验收门槛：用只有图片中存在的随机内容验证所选模型确实读取了像素，检查实际请求携带图像；另验界面图片显示。原始 Skill 的代表性 JS 操作序列能在 Ryn 中运行，挂起审批后不重跑先前动作，任务结束后会话及 helper 正确清理。不支持图像的路由必须明确阻止依赖视觉的动作。

## 阶段五 对齐配置和运行界面

扩展页分别显示插件启用、原生引擎就绪、桌面权限、会话连接和所选模型视觉能力。缺依赖、权限不足、模型图像不支持、窗口状态过期和进程失联给出不同的恢复入口。

任务中展示当前目标窗口、最近观察、图片、正在执行的动作与可用的停止操作。图片已保存、图片已显示和模型已观察必须有可核验的分别状态。连接成功不等于整条电脑控制链已可用。

验收门槛：首次设置、模型切换、撤权、重连、中断及异常恢复都能通过界面完成，状态来源是真实运行结果。

## 阶段六 同场景对照和真实应用验收

先固定 Codex 与 Ryn 的操作场景、观察条件、重复次数及性能口径，再执行对照。成功率、错误目标、重复动作、取消响应、进程残留和动作耗时分别记录；模型推理耗时与原生控制耗时分开。性能门槛在基线完成后冻结，不因失败临时放宽。

| 验收层级 | 完成条件 |
| --- | --- |
| 工具协议 | API 参数、返回、窗口与快照生命周期符合冻结的契约 |
| 原生行为 | 标准窗口、焦点、遮挡、多屏、输入和取消在固定场景通过；无错误目标或重复写入 |
| 模型视觉 | 每条标为支持的路由都完成实际图像传输与观察验证 |
| Skill 运行 | 原始电脑控制 Skill 的代表序列能在兼容运行时执行并正确审批、输出和清理 |
| 故障恢复 | 断连、撤权、崩溃、并发和 unknown 不丢诊断、不重放动作 |
| 真实应用 | 企业微信这类弱 UIA 界面也能完成观察、定位、输入和结果核验 |

真实发送只进行一次：依据既有用户授权，确认唯一的周英俊单人会话、准备精确文本“测试电脑控制”、核对后发送并只读确认。批量稳定性测试使用自有测试窗口，不向真实联系人重复发送。若发送结果未知，保留证据并停止重发。

## 开发分工和完成标准

Codex 冻结契约、继续必要的 REA / 行为取证、审查实现并独立验收。Gemini 4 负责原生核心、运行时及前后端代码和必要项目测试。可并行开发原生核心、模型图像适配与界面；共享协议和动作授权入口由单一设计管理，按上述门槛集成。

每阶段交付实际代码、测试、对照结果和未通过项。最终只有完整能力矩阵在声明的平台与模型路由上通过，才称该范围对齐 Codex。不同模型的决策能力仍需分别评估，工具兼容不能保证它们在任意任务上作出相同决定。

当前正在并行开发共享 MCP 可靠性修复、Ryn 原生控制核心、模型图像接入与隔离 JS/Skill 运行时。每条链路验收后再集成；既有企业微信任务仍未完成发送。
