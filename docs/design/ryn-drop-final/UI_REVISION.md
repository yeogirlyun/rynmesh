# 设备页布局修订 · 2026-10-13

用户在实现过程中提供原设备页截图，确认原来的设备管理 UI 更合适，允许它与首页采用不同布局。本修订覆盖先前「设备页默认显示网络图」的要求。

- 首页保留现有网络拓扑总览。
- 设备页使用原来的左右分栏：左侧设备列表，右侧设备详情和访问权限。保留原 DeviceArt 图标、私人备注、设备 ID、编辑详情、共享服务、设备同步和连接详情入口。
- 设备工作区页签为「设备列表／会话／传输」；列表分组为「我的设备／发现的设备」。发现分组中展示真实关系与可用能力，不把未配对设备当作已授权设备。
- 在线与离线设备都支持右键及可见的「…」菜单；菜单提供文件、文件夹、消息、传输记录和连接详情。当前设备不能给自己发送。
- 详情面板显示发送文件和发消息入口。发送仍需文件确认。拖放设备行也打开同一确认面板。
- 会话保留扁平布局，文件消息只有一层淡底；列表详情使用原来单层面板，不加入包住整个工作区的大卡片。
- 窄屏列表和详情上下排列；设备菜单使用底部操作表；会话采用列表与会话内容间的单栏导航。

当前产品代码为 `webapp/src/personal/drop/DeviceOverview.tsx` 和 `DevicesWorkspace.tsx`。原 `index.html`／`source.html` 不再代表设备列表页最新外观，保留历史交互参考；无需让实现回退去匹配其中的网络图。

## 设备消息界面再次修订 · 2026-10-13 晚

以实际应用的新界面为准，本节覆盖上面的「会话／传输」旧命名。

- 页签改为「设备列表／设备消息／传输记录」。设备主页面不再叠加同义的外层导航，设备同步仍有独立入口。
- 设备消息左栏固定显示本机身份，再展示能与它通信的设备；已选设备用浅色底和左侧强调线标识，保留右键与「…」菜单。
- 消息区域顶部明确呈现本机与对端的设备图标、名称以及连接线路；线路显示实际连接状态，可打开连接详情。
- 每条消息显示来源设备及「本机发出／对端发来」，本机消息深色靠右，对端消息浅色靠左。输入区持续显示实际接收设备。
- 设备列表保留左列表、右详情结构，减去重复卡片边框；首页拓扑及其他产品页面布局不在本次重设计范围。
- 文件收发、未读、中文输入法保护、逐设备草稿、连接详情及菜单动作保持真实接口行为。

## 紧凑会话修订 · 2026-10-13 夜

本节替代上一版的大幅双端连接图；以产品代码和以下实机节点页面截图为准。

- 设备消息页的标题、三个页签及设备操作合并为一条 62 px 工具栏，取消大标题副文案。
- 会话头部约 74 px：对端名称为主，本机名称、实际连接路径及加密标识为辅。点击状态查看连接详情，发送文件与菜单放在右侧。不再显示重复的「设备之间的消息」标题和大连接图。
- 会话列表缩至 232 px，保留本机身份、对端状态、最近消息、右键菜单。
- 输入区为一层细边框、约 105 px 高的编辑框，聚焦时边框加强；占位文字说明实际接收设备。消息区域独立滚动，输入区始终可见。
- 消息继续区分设备来源与收发方向，去掉时间行中重复的设备名。
- 1260×800 窗口：消息区 466 px 高，输入框底边 784 px；1440×960 窗口：消息区 626 px 高。390×844 手机布局无横向或整页纵向溢出。浅色、深色均已检查。
- 构建与 10 项既有 Drop 测试通过；真实节点页面检查了右键菜单保留草稿、连接详情及设备列表切换。本次没有额外发送测试消息，也没有重测 AI 或文件传输链路。
