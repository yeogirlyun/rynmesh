# Ryn Drop 接手与实现记录

更新：2026-10-13。状态：已完成两个真实 Windows 节点的安装、邀请入组、双向消息和 LAN 文件／文件夹传输验收；**尚未达到公网 NAT 穿透及真实 100 GB 的整体交付门槛**。

## 接手时的代码

Claude 已编写 `rynmesh/drop/` 的签名消息、加密流式文件、SQLite 持久化、块校验、暂停续传与接收权限接口；前端已编写主要界面组件、Tauri 文件选择桥接和中英文文案。不是从零开始。

接手时无法构建：缺少 `drop.css`。`DropProvider` 没有挂入 App，组件只能读取禁用状态；接收弹窗未挂载，全局请求入口也缺失。后端 15 项初始测试通过，但当时没有前端联调证据。原公网 CLI 引擎没有接入这个工作区。

## 已补齐和修复

- 挂载全局 DropProvider、接收对话框和持续可访问的传输／接收入口，各页面订阅同一任务。
- 按最新用户要求恢复列表／详情设备管理页，保留首页拓扑、原图标、私人备注、编辑、共享和访问权限；追加右键菜单、发送文件、消息、会话与传输页。见 UI_REVISION.md。
- 补全浅色／深色、桌面／窄屏样式。会话采用单分隔线和开放输入区；窄屏菜单是底部操作表。
- 修复浏览器批次 ID 与后端 hex 约束不一致造成的上传失败；文件仍直接以 File 请求体上传，不转换 Base64。关闭确认流程会取消未完成上传，不在关闭后新建传输。
- 修复消息回执丢失后的重试去重，复用原 client_id；延迟返回的会话历史不会覆盖刚收到的实时消息。
- 修复接收空间不足时弹窗被当成成功关闭；失败任务不再混进「已完成」过滤。
- 修复右键菜单首次聚焦造成页面滚动并立即关闭；保留键盘导航、Esc、焦点返回。
- 签名响应绑定本次请求 nonce，不能把旧响应重放为新任务回执。
- 接收目录提交先持久记录所有目标路径，重启时重新校验已经提交的文件，保持同一冲突改名目录；提交不覆盖已有文件，拒绝重复 file_id 和文件／父目录冲突。

## 尚未完成与下一步

1. 公网 NAT 穿透尚未接入。当前 Drop 通过 LAN 地址或可达公网 HTTP(S) 端点直连；能力接口如实返回 `nat_traversal: false`、中继不可用。现有 `peer_transit_service.py` 有 ICE／中转引擎及 2 GiB 默认限制，不能只删除该常量或把它的路径冒充已经接入的 Drop 路径。下一步需统一已确认的 offer、身份、接收授权、任务状态和恢复接口，再接入其数据通道。
2. 真实 100 GB LAN／跨公网传输、跨机器断网与重启、峰值内存／磁盘／性能证据尚未取得。本次大偏移测试证明了数值表示，不证明真实大文件验收完成。
3. 已找到仓库内 Windows Rust 工具链并完成 Tauri／NSIS 构建，安装至两台真实 Windows。文件选择命令已编译；此次发送通过浏览器文件选择，以及远端已安装节点的本地路径 API，尚未操作原生系统文件选择对话框。
4. 浏览器暂存的孤立上传回收、空目录保留、较大数量文件的恢复／历史分页、断线过程中目录提交冲突等仍需补充覆盖。当前浏览器上传需在本机额外暂存一份数据；桌面路径发送不需要这个完整副本。
5. 不实现 LocalSend 兼容、原生手机 App、匿名互联网链接或离线云托管；这些仍不属于本次范围。

已按用户授权安装到当前电脑和 172.16.8.82，未公开发布。仓库中另有用户／其他任务未提交的 AI 工作区等改动，本次未将它们当作 Drop 实现的一部分。
