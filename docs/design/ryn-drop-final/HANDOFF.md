# Ryn 设备互传 UI 实现说明

> 最新用户修订优先：设备页恢复原列表／详情布局，网络图仅保留在首页。参见 [UI_REVISION.md](UI_REVISION.md)。本文其余消息、文件、安全、体积、右键操作和验收约束继续适用。

用户确认基线：2026 年 10 月 13 日。最终入口为 docs/design/ryn-drop-final/index.html，可编辑源码为同目录 source.html。本文描述必须实现的产品行为；原型的模拟捷径在末尾单独列出。早期 ryn-drop-v1、ryn-drop-v2 和旧规划中与本文冲突的导航、卡片布局、LocalSend 兼容或大小上限，不再作为实现依据。

本次设计把文件发送和节点消息放进现有「设备」工作区。设备页默认展示可操作的网络连线图，选中节点后可发送文件或消息，也可使用节点的操作菜单。在设备会话中查看文字、链接和文件，在传输页统一管理任务。界面延续现有 PersonalShell 的蓝灰色调与侧栏结构，页面使用开放布局，避免大圆角容器嵌套小卡片。此目录是设计交付，不是已经接入传输引擎的产品代码。

## 已确定的产品方向

- 不增加顶层 Send 导航。设备页面下设「设备网络」「会话」「传输」三个页签。
- 设备网络中的「⋯」菜单包含发送文件、发送文件夹、发送消息、传输记录、连接详情。支持把文件拖到指定设备节点；选中节点后，下方的一行设备详情提供快捷发送和消息操作。
- 桌面支持右键设备节点、离线设备名称和会话列表中的设备，直接打开同一组操作。网络图右键时选定该设备；会话列表右键只确定菜单操作对象，不悄悄改变正在编辑消息的接收端。菜单顶部显示设备名，菜单跟随点击位置并避开窗口边缘。空白区域保持浏览器原生菜单；左键空白、Esc、滚动或窗口尺寸变化关闭自定义菜单。支持 Shift+F10、菜单键、上下方向键、Home/End 和 Enter。保留「⋯」作为触屏与键盘入口。
- 节点之间支持文字和链接。以设备身份区分发送端与接收端，同一对设备的文件和消息共用会话。
- LAN 与公网 P2P 直连均不设人为文件大小上限。100 GB 是正常用例，不出现升级会员或 2 GiB / 10 GiB 上限文案。
- 手机 App 后续开发。原型中的 iPhone 与窄屏布局展示未来形态，桌面首版不应把尚未发布的手机客户端当成真实在线设备。
- 首版不实现 LocalSend 兼容。Ryn 需要设备身份、跨网连接、节点会话和统一传输状态，先把这些行为做完整。若以后用户确有和未安装 Ryn 的手机互传需求，可另行评估局域网兼容入口，本次不建设此功能。

## 页面与交互

### 设备网络

设备按「我的设备」「好友设备」「附近」切换，不要再按 LAN 与公网分成两套操作。连接图以本机为起点：局域网设备直接连到本机，公网设备通过标记为「互联网」的路径示意连接。互联网图标仅表示跨网路径，不代表强制经过 Ryn 中心服务器；只有实际中继时才显示中继标记。节点显示名称、在线状态、当前路径和延迟；选中后的详情行补充系统信息。

桌面使用横向展开的开放连接图，不给每个设备再套完整卡片。局域网、公网和中继通过线型与文字共同区分。离线设备单列在图下方的「未连接」行，保留操作，不画成已建立的连接。图使用真实布局测量与 ResizeObserver 重算线条，不能缩放整张固定尺寸 SVG 导致文字变小。节点接受文件拖放，但松开后必须打开带接收端名称与文件清单的发送确认面板，不立即发送。菜单锚定操作按钮；点击空白区域、Esc 或完成操作后收起。设备菜单和弹层应使用现有可访问性组件。

项目原有网络图位于首页 PersonalHome，挂载点为 webapp/src/personal/Pages.tsx 的 DeviceTopology；组件在 webapp/src/personal/DeviceTopology.tsx。首页继续保留总览，设备页复用并扩展连接图为可操作工作区，不要删除首页图，也不要维护两套互相矛盾的网络关系数据。当前个人设备页面为 PersonalDevices，经 App.tsx 的 devices 路由挂载。

本机应单独标记，不能向自己发起点对点任务。示例侧栏底部和图中的「工作电脑」代表同一本机，其余设备节点代表可操作的目标设备。

「传输记录」菜单在正式版中应打开按该设备筛选的记录，并允许清除筛选。设计原型目前展示全局示例并说明这一点。

### 发送面板

桌面右侧面板宽约 435 px。顶部先显示明确的目标设备，再显示文件清单、总数、大小、可选留言。文件可移除和追加，清空后发送按钮禁用。关闭面板不影响已经创建的传输任务。

操作文案按设备状态区分：在线已配对设备显示「发送」；离线设备显示「加入待发送」；未配对附近设备显示「核对并发送」。文件夹发送复用同一面板，展示目录名、文件数量和总大小，支持展开清单。

创建任务前完成权限、文件可读性、接收路径、空间和连接能力检查。接收端空间未知时显示「等待接收端检查空间」，不要伪造可用容量。磁盘不足时说明需要与可用空间，提供更改位置或稍后重试。

大文件采用流式读写和分块校验。不能先把 100 GB 文件读进浏览器内存或转换成 Base64。若当前 Web 运行环境无法提供所需的持久文件句柄，应明确提示在桌面 App 中发送；不要悄悄改变产品大小限制。目录访问与原始文件句柄在重启后失效时，让用户重新选择源文件并验证一致性后续传。

### 设备会话

会话头部同时显示目标设备、所属关系、在线状态、实际连接路径。文字气泡与文件卡片保留来源设备和时间。自己发出的文字和文件统一右对齐；接收内容左对齐。

消息状态至少区分「等待设备上线」「发送中」「已送达」「发送失败」。只有对端确认收取后才能显示已送达；没有真实阅读回执就不显示已读。离线消息首先存在发送端本机，本版本不承诺后台服务器离线存储。

文件以独立卡片出现在时间线，可显示进度、速度、剩余时间、路径和暂停操作。文件不走现有小附件限制的消息载荷；消息只引用 transferId。会话列表预览最新文字或文件名，未读数源自真实数据，不写死。

设备会话绑定设备身份，不绑定可变的显示名称、IP 地址或好友昵称。不要把 NAS 的自动传输事件伪装成用户说的话；原型中的文字回复代表该设备用户的输入，自动事件应采用系统消息样式。

### 接收确认

好友设备默认需确认，每次请求清楚展示发送方、设备、大小、数量与保存位置。「以后自动接收」默认不勾选，授权范围仅为这台设备，可在其接收偏好撤销。

自己的已配对设备可支持自动接收，但必须依据实际接收偏好。首次设置明确告知保存位置和自动接收行为。不要仅凭展示名判断属于自己的设备。

未配对设备只允许局域网发现。首次文件或消息请求都必须核对双方从真实加密握手产生的短验证码，并经接收端接受。原型展示的 482 916 只是排版示例，不能复用到正式代码。身份变化时重新验证，不沿用旧授权。

### 传输页

页签下提供「全部」「进行中」「已完成」过滤，必要时显示设备过滤条件。每条记录显示方向、接收端、文件大小、路径、进度和状态对应动作。文件只有校验完成且提交到最终路径成功后才显示完成。

| 状态 | 主要文案 | 操作 |
| --- | --- | --- |
| 等待连接 | 正在连接目标设备 | 取消 |
| 等待上线 | 设备离线，进度保留在本机 | 重试、取消 |
| 等待接受 | 等待对方接收 | 取消 |
| 传输中 | 64.8 / 100 GB，42.6 MB/s，约 14 分钟 | 暂停、取消、打开会话 |
| 已暂停 | 已暂停，64.8 GB 进度已保留 | 继续、取消 |
| 重新连接 | 连接中断，正在恢复 | 稍后重试、取消 |
| 校验中 | 传输完毕，正在校验文件 | 查看详情 |
| 已完成 | 已接收，文件已校验 | 打开文件、显示所在文件夹 |
| 空间不足 | 需要 100 GB，可用 64 GB | 更改位置、重试 |
| 拒绝或取消 | 对方拒绝 / 已取消 | 再次发送 |
| 源文件变化 | 源文件已变化，无法继续原任务 | 重新选择并创建任务 |
| 校验失败 | 文件校验失败 | 重试受损块、查看详情 |

任务状态由一个统一存储维护，设备页底部、会话卡片、传输页和全局任务入口都订阅同一个任务。暂停、恢复、取消必须幂等，不能每次重试创建重复传输。

## 连接信息与限制

产品展示三种路径：「局域网直连」「公网直连」「中继连接」。默认自动选择，用户无需理解 NAT 或 UDP 等术语。技术信息仅在连接详情中展示。

P2P 直连不设人为文件大小上限，不代表中继和离线托管也无限。中继可用额度、大小限制、费用与剩余空间必须从能力接口读取。原型中的中继示例不代表已经实现或承诺任何额度。

当 100 GB 直连任务失去连接时，优先尝试恢复。若需要改走受限或收费中继，先核对能力；会产生新费用、违反额度或改变用户已确认范围时，暂停并明确确认。不能自动把用户理解的无限直连任务转成付费中继任务。连接路径变化后同步更新所有位置的标签，保留同一任务和已传字节。

现有公网引擎的上限、流式能力和断点恢复需由实现者重新审计。不能仅删前端校验便宣称支持 100 GB；本次 UI 交付不证明现有引擎具备该能力。

## 移动端

窄屏隐藏桌面侧栏，网络图改为纵向展开，保留连线和设备名称，不退回卡片墙。设备操作菜单正式实现使用底部操作表；发送面板成为全屏流程。移动端保留设备、会话、传输的一致信息架构，系统分享扩展未来可直接选择 Ryn 设备。

原型在窄屏压缩会话选择栏方便同时审阅。正式移动 App 使用「会话列表 → 单个设备会话 → 返回」的单栏导航，不把很多设备挤在顶部。输入框随软键盘移动，考虑安全区域，触控目标至少 44 px。

手机 App 阶段还需设计系统文件选择、照片访问权限、后台任务被系统暂停、通知恢复、扫码配对和系统分享。首版桌面实现保留这些接口，不把原型响应式布局称为已完成手机 App。

## 视觉与组件

沿用 webapp/src/personal/personal.css 中的语义令牌，包括 --pf-bg、--pf-sidebar、--pf-panel、--pf-text、--pf-muted、--pf-line、--pf-blue、--pf-selection。原型为独立预览使用了等价的 --rd-* 变量，生产实现应映射到现有令牌，避免第二套全局主题。

使用 Segoe UI 与中文系统字体；页面标题约 28 px，设备名称约 13–15 px，正文 13–14 px。页面、连接图、会话工作区、传输记录均不使用外层圆角卡片。会话仅用一条竖向分隔线区分列表与内容，输入区域只有上分隔线；文件消息保留一层淡底，移除边框、文件图标容器与嵌套按钮框。传输记录使用分隔行。圆角与浮层阴影留给真实菜单和弹窗。图标复用 lucide-react。浅色以白底、蓝灰分隔线和深蓝主按钮为主，深色沿用现有蓝灰背景。状态同时使用文字和图形，不只用颜色。

建议拆分 DeviceActionsMenu、DeviceSendSheet、DeviceConversation、TransferCard、TransferList、IncomingTransferDialog、ConnectionDetails。优先复用项目已有对话框、文件选择桥接、设备模型和通知系统。实际挂载位置需核对当前 App 路由；本项目同时存在多套设备界面，不应只改未被用户使用的旧页面。

## 实现顺序与验收

1. 按原型搭建组件、路由与本地状态，完成桌面和窄屏可访问性检查。
2. 接入真实设备与消息通道，验证已送达语义、离线队列、权限和设备身份。
3. 接入流式文件传输，把所有界面的 TransferCard 接到同一个任务。
4. 验证 LAN、公网 P2P、中继受限、断网恢复、取消、接收拒绝、空间不足和目录发送。
5. 在真实设备上验证 100 GB 文件及应用重启后的恢复、最终文件哈希、磁盘占用和内存稳定性，再对外声明支持大文件。

UI 验收至少覆盖 1440、1024、736、390、320 px；键盘可打开菜单，Esc 关闭弹层，焦点回到发起按钮，中文输入法选词时 Enter 不误发；文件名和路径必须按文本渲染。生产弹层应使用现有组件处理焦点与背景不可交互，不能直接复制原型的轻量事件处理。

本原型可体验菜单、文件确认、节点消息、暂停恢复、重试、接收确认、附近设备校验示意和离线排队。演示速度、容量、设备、验证码和时间全部是固定样例。取消操作保留主示例为暂停状态以方便继续评审；接收操作仅反馈模拟结果；设备历史暂未实现真实筛选。这些演示捷径不能进入正式实现。

## 数据和接口边界

先审计现有实现，再决定具体模块与接口名称。下列内容是行为契约，不要求另起一套引擎或照搬新的 API 路径。

| 对象 | 实现要求 |
| --- | --- |
| 设备引用 | 使用已验证的稳定设备身份，名称和地址仅用于展示与寻址；表示所有权、配对状态、在线状态、能力与实际路径 |
| 发送请求 | 明确发送端、接收端、offerId、文件或目录清单、总字节数、接收策略；先确认再传输，拒绝与过期必须终止请求 |
| 消息 | messageId、发送端与接收端身份、正文、时间和送达状态；确认与重试去重，自动事件和用户文字分开 |
| 传输任务 | transferId、offerId、清单、状态、已确认字节数、恢复信息、当前路径、速度、剩余时间、错误及可执行操作；本地持久化，跨页面共用 |
| 能力检查 | 可用传输方式、是否可流式发送、接收空间、目录支持、中继额度与限制；未知值明确展示，不以默认真或默认零冒充已检查 |
| 进度事件 | 携带 taskId 与可排序版本或序号；重复和乱序事件不回退已确认进度，UI 合并高频更新；重连先取得任务快照 |

大文件偏移、块编号、长度和数据库字段不得使用会在 2 GB 或 4 GB 溢出的整型。100 GB 的业务目标不是新的硬上限。跨语言序列化必须保留整数精度，超出 JavaScript 安全整数范围时使用约定的无损表示。

接收端将未完成文件写到临时位置，完成校验后再提交最终文件。目录清单必须限制在用户选择的目标目录内，处理路径穿越、绝对路径、名称冲突、符号链接与覆盖策略；不能默默覆盖用户现有文件。取消、拒绝和失败后的临时文件清理要有明确规则。

消息、文件与恢复请求必须校验设备身份和会话授权。采用项目已有且经验证的密码方案；不能把界面上的锁图标视为加密实现。NAS 等无交互节点按实际能力显示接收偏好或消息收件箱，不伪造即时人工回复。

## 正式完成的验收门槛

| 范围 | 必须证明的结果 |
| --- | --- |
| 视觉一致性 | 实际设备页有可操作连接图，首页总览仍在；无卡片墙与大框套小框；真实界面截图对照本目录基线 |
| 右键菜单 | 在线、离线和会话设备可打开；对象准确，边缘不裁切；菜单动作可执行，关闭与键盘导航正常；不改变未发送草稿的目标 |
| 消息 | 两个真实节点互发文字和链接；等待、失败、重试、送达语义真实；重复确认不重复显示消息；中文输入法不误发 |
| 文件和目录 | 两个真实节点发送单文件、多文件和目录，确认目标、接收位置与冲突处理；文件进入同一设备会话与全局记录 |
| 大文件 | 真实 100 GB 文件经 LAN 和公网 P2P 路径验证；记录路径证据、耗时、字节数、内存与空间使用、最终校验结果 |
