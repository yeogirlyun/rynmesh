# 本地模型导入验收 · 2026-09-24

当前实现遵循用户最后确认：模型由用户选择本地文件，Qwen 只作为测试样本；不提供预设模型下载。

## 已实现

- AI 来源 → 添加 → 本地模型，首屏只有“选择模型文件”主操作。
- 桌面原生 GGUF 文件选择器；网页文件选择、头部预检、文件名/大小预览、确认后流式导入。
- 单文件 GGUF v3；有界元数据、架构、量化、张量范围检查；导入后保留 SHA，启动前验证未被改变。
- 原文件不变；受管副本安装；固定版本且校验 SHA 的 Windows / Apple Silicon 运行组件。
- 用户模型名称、指纹和独立服务 ID 自动接入本机 API 与现有节点服务管理。
- 真实回答自测后才显示运行；停止等待正在处理的回答；启动、停止、卸载、随 Ryn 启动、共享偏好。
- 缺少运行组件时才下载组件。应用代码已移除固定 Qwen 模型 URL/尺寸/哈希白名单和模型下载操作。

## 实机验证

环境：Windows x64，隔离测试节点 `127.0.0.1:18895`，数据位于 `.codex-tmp/local-model-acceptance/node`。

1. 从网页文件选择器选择本地 `Qwen3-1.7B-Q8_0.gguf`，1834426016 字节。
2. 导入、复制校验、Windows CPU 引擎启动、回答自测成功，界面显示“正在运行”。
3. 经 Ryn `/v1/chat/completions` 调用，HTTP 200，返回 `LOCAL_IMPORT_OK`。临时验收 API key 已撤销。
4. 开启随 Ryn 启动，再手动停止，偏好仍为开启；重启测试节点，模型自动启动成功。
5. 在运行中关闭自动启动，当前模型继续运行；关闭节点后 llama-server 进程退出；重启后保持停止。
6. 卸载测试副本，回到初始导入页；原文件 SHA-256 未变化。

实测发现并修复了普通 API 1 MiB 请求上限误拦大模型文件的问题。仅专用导入端点改为受认证保护的流式写盘、Content-Length/64 GiB/磁盘空间限制和读取超时；普通聊天 API 仍保留原有上限。

## 范围与未验收部分

- 当前为本地开发版与预览，尚未重新打包分发安装程序。
- Mac Metal 和 Windows NVIDIA 分支已实现，当前实机只验证 Windows CPU；不能将其表述为跨平台实机验收完成。
- 原生桌面文件选择器已编译检查，真实大文件端到端验收走网页入口。
- 目前一个受管模型；更换模型先卸载受管副本再导入。尚不支持分片、IQ 系列量化、LoRA 或多模态输入。
- 共享复用现有个人空间服务路径并验证权限拦截，本轮未进行两台物理设备的端到端共享验收。
