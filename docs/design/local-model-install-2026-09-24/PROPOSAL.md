# 本地模型一键安装与导入

## 当前确认方案（覆盖下方历史方案）

用户明确：模型由用户选择本地文件提供；找小 Qwen 仅用于开发测试。产品不预设模型、不下载模型权重、不以固定文件 SHA 限制用户选择。

- 入口：AI 来源 → 添加 → 本地模型 → **选择模型文件** → **导入并启动**。
- 文件限制：单个完整 GGUF v3、最大 64 GiB；当前支持 Qwen2/3/3.5、Llama、Gemma1/2/3、Phi2/3 架构及常规 GGML 浮点和 Q2_K/Q3_K/Q4/Q5/Q6_K/Q8 量化。拒绝分片、压缩包、LoRA、脚本、未知架构/量化。实际加载和回答自测成功后才标记运行。
- 桌面使用原生文件选择器、直接读取本地文件；网页选择文件后流式传给当前节点。原文件保留，只管理复制后的文件。
- 分平台自动准备固定版本、校验过的 llama.cpp 组件。界面明确提示缺少运行组件才下载组件，没有模型下载按钮。
- 首版一个受管模型。更换时卸载当前副本后导入另一个文件；卸载不删除原文件。模型服务 ID 按实际 SHA 区分。
- 已导入状态保留启动/停止、更多设置、共享开关。
- **随 Ryn 启动**默认关闭，只控制下一次软件启动；修改开关不会立即启动，手动停止不会关闭该偏好。
- Windows x64 CPU/NVIDIA 与 Apple Silicon Mac 分流。Windows 实测不能代替 Mac 实机验收。

## 第二轮：精简设计（优先于下方首轮布局）

用户反馈：“可以，但是看着有点复杂，能简化一些吗？另外，可以在这里一键控制启动和关闭吗”。

入口仍为 AI 来源 → 添加 → 本地模型。默认打开简短模型面板，不再呈现三页签、步骤条、系统架构表、引擎信息和安装路径表单。

### 首次使用

- 模型名：Qwen3-1.7B。
- 一句话：在这台电脑上运行。
- 下载约 1.83 GB，运行环境自动配置；实际需要的总空间仍由后台检查。
- 唯一主按钮：一键安装。
- 次入口：导入已有模型文件；旁边说明仅支持已验证的 GGUF 文件。
- 系统自动匹配 Mac 或 Windows；不要求用户选择系统或引擎。
- 连接已有服务移到添加来源中的次入口，复用现有表单。

点击安装后在相同面板内用一条进度条和一句当前状态替代按钮区；不用单独多步骤向导。下载中可以取消或关闭面板；AI 来源行和任务页均能重新打开进度。只有失败时展开必要的原因及重试入口。

### 安装完成与日常控制

同一个模型面板只保留：模型名、运行状态、开始聊天、启动/停止、分享给我的设备。更多菜单放模型详情、存储位置和卸载。

AI 来源列表中的受管模型行也直接显示启动/停止按钮，不必进入详情即可控制。只有 Ryn 管理的模型进程才提供此按钮；外部 API 或用户自行运行的 Ollama 服务不误显示为可由 Ryn 关闭。

| 状态 | 同位置按钮 | 行为 |
| --- | --- | --- |
| 未安装 | 一键安装 | 检查、安装、启动、自测并接入 |
| 安装中 | 显示进度 / 取消 | 避免重复启动安装任务 |
| 已停止 | 启动 | 使用本机已有文件启动，不重复下载 |
| 启动中 | 正在启动… | 按钮禁用，等待服务就绪 |
| 运行中 | 停止 | 停止受管模型进程，保留文件 |
| 正在处理请求后点击停止 | 正在停止… | 拒绝新请求，等待当前请求结束后停止；显示“当前回答完成后停止” |
| 错误 | 重试 | 展示具体失败原因，按失败阶段重试 |

“停止”只影响该模型，不关闭 Ryn 节点或其他 AI 来源。模型停止后释放其进程占用的资源、撤销可用状态，远端不再将其视作可接单服务。保留共享偏好；再次启动并就绪后按原授权恢复可用。停止状态需持久化，刷新界面不自动启动。共享默认关闭，未加入个人空间时仅在用户操作共享时提示如何设置。

第二轮设计采用单一精简方向，图中两个面板表示首次安装与安装后的两个状态，不是两套方案。文件格式、完整性校验、平台兼容检查仍保留，只将技术细节从主界面移到自动检查及必要的错误提示。

## 用户目标

不懂部署的用户可在 Ryn 中选择推荐模型，或导入受支持的模型文件。Ryn 自动检查设备、准备适合操作系统的运行程序、启动模型、完成真实问答测试并接入本机节点。用户随后决定是否共享给个人空间设备。

## 入口与信息结构

主入口沿用：服务 → AI 来源 → 添加 → 本地模型。不增加顶级导航。

进入后呈现三种接入方式：

1. 一键安装（默认）：展示首个经过验证的推荐模型、文件大小、设备检查结果、安装位置和主按钮。
2. 导入文件：通过原生文件选择器或拖拽选择本机文件，先校验再安装。
3. 连接已有服务：保留现有 Ollama、LM Studio、自定义兼容 API 接入表单。

本机安装只操作当前节点所在设备；查看其他设备来源时，显示“请在该设备上安装”，首版不提供远程下发安装。浏览器访问其他机器上的节点时，不把浏览器本机路径误认为服务端路径；文件导入首版限定桌面端原生文件选择。

## 三个待选视觉布局

## 完整流程及界面状态

### 安装前

显示模型名、来源、下载大小、当前设备系统/架构、运行方式、空间是否够用。支持更改模型存储目录。引擎所需空间、临时空间和运行内存必须动态检测或基于实际验证，不能将模型文件大小当作显存需求。

主按钮为“检查并安装”；导入模式主按钮为“验证并导入”。端口、API 地址、引擎路径不出现在主流程。上下文等参数放在高级设置，首版使用经过验证的保守默认值。

### 安装中

阶段：检查设备 → 获取/复制模型 → 校验文件 → 准备运行环境 → 启动与问答测试 → 接入本机。

下载展示实际字节和百分比；无法测量的启动阶段使用不定进度，禁止伪造进度。提供取消；关闭弹窗/页面后任务继续，可在任务页及对应 AI 来源行恢复查看。节点退出后的未完成任务显示中断，经过校验后支持继续下载或重试。

### 安装成功

只有真实问答测试通过后显示“已就绪”，来源自动加入当前本机模型列表。主按钮“开始聊天”，次入口“共享设置”；共享默认关闭。失败不显示可用模型或虚假成功。

来源行显示“本地模型 · Ryn 管理”，并区分安装中、运行中、已停止、出错。详情提供启动/停止、重试、存储位置和卸载。新建安装不覆盖已有来源或模型别名。

### 共享

用户开启“分享给我的个人空间节点”。未加入空间或未启用 AI 访问时，展示原因并链接个人空间设置。安装完成与共享授权是独立状态。模型权重和上游凭据不随共享传输。

### 失败与限制提示

- 文件格式不支持：本版仅接受支持列表中的单文件 GGUF。
- 扩展名正确但内容损坏：模型文件无效，请重新下载。
- 架构/量化/校验值不匹配：此模型尚未通过本版兼容性验证。
- 内存或磁盘不足：显示当前可用值与预计需求，允许更换目录或模型。
- 下载失败：重试/继续下载；不静默改用未知镜像。
- GPU 不可用：说明原因；若可使用 CPU，则给出明确的 CPU 运行选择，避免把运行速度当作已保证。
- 启动或自测失败：保留模型文件，提供重试与简明诊断。

## 首版建议限制（待确认）

| 项目 | 建议 |
| --- | --- |
| 模型格式 | 单文件 `.gguf`；同时校验文件头、元数据、架构、量化类型、完整性 |
| 支持范围 | 先只放行首个验收模型的确切版本及 SHA-256；之后通过受控模型目录扩展，不能仅凭后缀接受任意模型 |
| 暂不接受 | ZIP/压缩包、Safetensors、PyTorch bin/pt/pth、模型分片、LoRA、用户脚本或可执行安装包 |
| 导入语义 | 校验成功后复制到 Ryn 管理目录，再从管理目录启动；UI 提前显示复制所需空间；不改写或删除原文件 |
| 下载来源 | 固定仓库 revision、文件名及 SHA-256；运行引擎也固定版本和校验信息 |
| 功能 | 先做文本聊天与现有文本 API；不因模型支持视觉就宣称图片/视频可用 |
| 并发 | 首版单个活动受管模型；安装新模型不自动停止现有任务，资源冲突时提示用户处理 |
| 联网 | 首次准备引擎/下载模型需联网；已有 GGUF 不等于完全离线安装，引擎未缓存时仍需下载 |
| 服务端口 | 自动分配本机回环端口，自动接入 Ryn；不暴露原始推理端口到公网 |

## 平台建议（待确认）

模型文件本身可共用；分平台的是运行引擎，不要求用户挑选“Mac 模型”或“Windows 模型”。

| 平台 | 首版候选范围 | 自动匹配策略 |
| --- | --- | --- |
| macOS | Apple Silicon / arm64 | 原生 llama.cpp + Metal；最低系统版本以固定引擎构建和实机验证为准 |
| Windows | x64 | 原生 llama.cpp；优先经验证的 NVIDIA GPU 路径，可兼容时提供 CPU 路径；检测 CPU 指令集及驱动 |
| Intel Mac / Windows ARM | 首版不开放一键安装 | 显示暂不支持，保留连接已有服务 |

不要求用户另装 Docker、Python 或 Ollama。引擎在应用用户目录内受管安装。Apple Silicon、Windows CPU 和 Windows NVIDIA 加速需分别验收；当前 Windows 开发环境的结果不能充当 macOS 实机验收。

引擎能力参考：https://github.com/ggml-org/llama.cpp 。最终固定版本及操作系统最低要求将在获准开发后核实并验收。

## 当前实现基线与下一步

当前仓库有硬件检测、受管下载、GGUF 导入、生命周期、自测、节点接入和共享基础。安装入口仍调用 Docker 受管路径，不能把这份设计称为已经完成的原生安装功能。

确认事项：候选模型、入口与视觉布局、文件支持范围、平台首版范围。得到用户确认后再实现原生引擎管理及 UI，并执行下载/导入 → 启动 → 真实问答 → 本机 API → 共享的验证。
