# AI 工作台：共享服务与本机 API 配套设计

日期：2026-09-23。状态：首版文本能力已接入，图中交互仍包含未实现的工作台 Agent 能力。

延续用户认可的深色 AI 工作台，补齐同一流程的三个页面；这些页面互相配套，不是互斥的视觉方案。

## 使用链路

笔记本其他程序 → 笔记本 Ryn 本地 API → 加密节点连接 → 家里 Ryn → 所选模型或 CLI。

家里节点负责服务适配与内部事件归一化；笔记本节点负责鉴权、别名路由和对外协议输出。现有本地推理 API 的默认入口为 `http://127.0.0.1:8791/v1`，具体端口以节点配置为准。

## 页面

1. **本机 API 接入**：位于笔记本，提供协议选择、Base URL、Model、项目密钥、复制配置、调用示例及测试入口。OpenAI base URL 带 `/v1`，Anthropic base URL 使用根地址；不同协议对应自己的示例。
2. **模型映射**：位于笔记本，将 `home-codex` 等调用名称映射到具体设备、服务和上游模型；显示经过检测的能力子集，目标离线明确报错。
3. **服务共享**：位于家里电脑，检测 CLI 安装与登录状态，设置工作台/API 可用方式、共享范围与工作台任务的目录和命令授权。

## 交互约束

- 本机 API 只供本机程序访问；其项目密钥不等于上游 CLI 的登录凭据。
- API 文本响应模式不隐式授予家里电脑的文件读写、命令执行权限。
- 外部程序的函数工具调用与 CLI 在家里执行工具是不同能力，必须分别适配与验证。
- 图中的文本、流式等能力状态仅为设计示例；实际能力以适配测试为准，不承诺完整厂商 API 兼容。
- CLI 服务使用的模型可能位于云端；节点传输加密不等于模型推理完全本地。
- 首版通过已安装并登录的 Codex CLI / Claude Code 执行文本请求；配置时做一次真实自检。服务发布要求个人空间 AI 访问策略。
- 首版 CLI API 不支持流式输出、客户端工具调用、图片或采样参数；工作台尚未实现目录挂载、命令审批和文件修改。
- Codex CLI 以主机登录用户运行；临时工作目录和只读沙箱不能保证它无法读取该用户可读的其他文件。仅向可信任的个人节点分享。
- 工作台与 API 请求的会话应隔离；后续实现需明确历史、取消、错误、用量及授权的映射。
- 当前既有远端推理 API 使用严格 P2P；新适配需延续该约束，不能静默引入 HTTP 或中继回退。
