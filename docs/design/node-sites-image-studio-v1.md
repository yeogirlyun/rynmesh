# 节点网页 + 做图（设计 v1，2026-11-13）

状态：第 1 步（节点网页通道）已实现，见 [NODE_SITES.md](../NODE_SITES.md)；第 2–6 步未开始。界面稿：Claude Design 画布「Ryn 做图窗口」（5 个画面）。

## 一句话

一台节点把本机的一个网页开放给指定的人；对方在 Ryn 里打开它，就像打开一个网站，但地址是那台节点，不经过公网服务器。做图是第一个这样的网页：页面和后台都在开放者的电脑上，用开放者电脑上的 GPT 出图。离线就是离线。

## 现状（读代码核实）

- 插件页面：`webapp/src/screens/ExtensionWebApp.tsx` 把插件声明的 `webApp.url`（HTTPS 或本机回环）直接放进沙箱 iframe。只有"本机或公网网址"两种来源，没有"另一台节点上的网页"。
- 节点应用（`rynmesh/node_apps`）：只把调用发给提供方，界面在调用方本机画，且只给好友。不是网页加载。
- 公司通道已上线：目录、设备探测（LAN → 直连 HTTP → P2P，`drop/engine.py` 的 `PeerDirectory`）、发送前向公司中心实时授权（`peer_providers/service.py:authorize`，目前只认 `model.invoke`、`message.text`）。
- P2P 单条消息最多 32 MB，分块传（`llm_package/p2p.py`），一张图（≤12 MB）够用。
- Ryn 给插件本地服务发服务令牌（`RYN_PLUGIN_SERVICE_TOKEN`），服务可以回调 Ryn。
- 本机出图：`llm_package/codex_image.py:generate`，用本机登录的 Codex，返回 PNG。Codex 回合输入支持图片（`cli_images.py`），参考图可行。

## 一、节点网页加载规则（Ryn 核心，通用，开源）

### 1. 开放方（提供网页的节点）
- **什么能开放**：本机插件声明 `ryn.site`（名字、图标、回环服务端口、入口路径）。装好默认不开放。
- **开放给谁**：开放者在 Ryn 里打开开关，选范围：全部公司同事 / 指定的人。v1 只做公司通道；好友、陌生节点以后复用同一套。
- **入口**：新的对等接口 `POST /api/peer/site/request`。每个请求都要：
  1. 调用方节点签名有效，且加密给本机消息密钥；
  2. 调用方在公司目录里，并通过公司中心实时授权新能力 `site.open`（按网页 ID）；授权结果缓存 60 秒，撤销后最多 60 秒内生效；
  3. 本机开关和范围允许；
  4. 限流：每人同时最多 4 个请求，每分钟 300 个。
- **转发给网页后台**：转到本机回环端口，加上 Ryn 写的身份头（调用方设备、成员 ID、名字）和服务令牌。后台必须校验服务令牌，否则本机任何程序都能冒充同事身份。调用方发来的 Cookie 和身份头一律丢弃，身份只认 Ryn 给的。

### 2. 打开方（同事的 Ryn）
- **独立来源**：每个远程网页在本机有自己的地址 `http://<网页键>.site.localhost:<网页端口>/`，网页端口是一个专门的本机端口，和 Ryn 控制接口（8791）分开。这样远程页面读不到 Ryn 的本地接口，也读不到别的网页的存储。
- **只有 Ryn 窗口能用**：子域键是 128 位随机密钥，只在 Ryn 里保存；网页端口只接受 Host 等于已登记键的请求（同时挡住 DNS 重绑定）。用户浏览器里别的网站猜不到地址，就没法借同事身份访问老板的节点。（原先设想的票据 Cookie 在 iframe 里属于第三方 Cookie，已放弃，见第三节。）
- **请求怎么走**：网页端口把每个 HTTP 请求打包（方法、路径、少量安全请求头、正文），加密签名后经已有路线（LAN → 直连 HTTP → P2P）发给开放方，回来的响应还原给 iframe。
- **大小和时间**：请求正文最多 25 MB（3 张参考图），响应最多 32 MB；单个请求 30 秒超时。耗时操作（出图）走"提交 → 拿任务号 → 每 2 秒查一次"，不靠长连接。v1 不支持 WebSocket。
- **页面限制**：网关给每个响应加 CSP，只允许访问自己（`default-src 'self' data: blob:`），远程页面不能连外网、不能把同事电脑上的东西传出去。iframe 只给 `allow-scripts allow-forms allow-same-origin allow-downloads`，不给 Ryn 的插件桥（工具、模型、消息、Agent 都不给）。
- **窗口外框由 Ryn 画**：顶部显示"子陵的电脑 · 做图 · 在线/离线"，相当于地址栏，页面伪造不了。
- **离线**：探测不到对方或请求失败 → Ryn 显示离线画面（画面 4），每 15 秒探测一次，恢复后自动重新加载。不排队、不代存。
- **在哪里看到**：公司目录里对在线的设备询问它开放了哪些网页（`GET /api/peer/site/list`，同样要授权），缓存最近一次结果；离线设备显示"离线"。

### 3. 公司中心要改的（小改动）
- `authorize` 接受 `site.open`（带网页 ID），规则：双方都是在职成员，开放方是发布人（沿用现有发布人名单）。
- 需要部署 hk036。

## 二、做图网页（第一个节点网页）

放在 Ryn 主程序里作为内置网页（不含公司内容，开源）；开放给谁由上面的规则决定。页面和后台都只在开放者电脑上跑。

| 小功能 | 说明 |
| --- | --- |
| 提交 | 用途尺寸（主图 1:1、海报 3:4、竖版 9:16、横幅 16:9、自定义），描述，图上文字，参考图 ≤3 张（PNG/JPG/WebP，每张 ≤8 MB，按文件头校验），张数 1/2/4（每张一个任务） |
| 排队 | 开放者电脑上一个队列，一次做一张，先到先做；返回排第几、大约多久开始；同事可取消自己的；开放者可停止、提前、取消 |
| 出图 | 后台通过服务令牌调用 Ryn 新接口"本机出图"→ `codex_image.generate`，带参考图和尺寸要求；单张超时 5 分钟；同时只跑 1 个 |
| 失败 | 分清原因给人看：GPT 额度用完、Codex 未登录、超时、被取消、内容被拒；可重试 |
| 作品 | 存开放者电脑（Ryn 数据目录），按同事分开，生成缩略图；同事只能看自己的；保留 90 天，可在设置里改 |
| 我的作品页 | 全部/进行中/已完成，详情大图，下载 PNG，再来一张（同参数），改这张（把结果当参考图再提交） |
| 我的做图服务（开放者看） | 开关、范围、模型状态、今天张数、队列管理、每人今天/30 天/失败次数 |
| 记录 | 每次出图记谁、何时、尺寸、用时、结果，只在本机 |

## 三、验证结果（2026-11-13，老板主机实测）

1. **子地址可用（Windows）**：Edge 158（和 Ryn 用的 WebView2 157 同一内核）打开 `http://<32位键>.site.localhost:<端口>/`，页面加载、同源 fetch 都正常；从 `tauri.localhost` 页面里用 iframe 嵌入也正常。服务端看到 iframe 导航是 `Sec-Fetch-Site: cross-site`，说明两者是不同站点，Cookie 会被当成第三方 Cookie。
   - **设计因此改为**：不用票据 Cookie。每个网页的子域键本身就是 128 位随机密钥（只有 Ryn 知道），网页端口只接受 Host 等于已登记键的请求；iframe `referrerPolicy=no-referrer`，CSP 禁外连，避免密钥外泄。
   - 没验证：Ryn 自己的 WebView2 窗口里实测（引擎相同，风险低，放到第 1 步验收）；macOS WKWebView（这里没有 Mac，不行就退回"每个网页一个本机端口"）。
2. **Codex 出图**（本机 codex-cli 0.167.0-alpha.3.2，模型 gpt-6.1-sol）：
   - 尺寸不能直接指定：Codex 出图工具发给接口的 `size` 固定为 `auto`（源码 `ext/image-generation/src/tool.rs`）。但比例跟着描述走：写"竖版 9:16"得到 941×1672，正好 9:16。
   - **设计因此改为**：把比例写进给 Codex 的描述；需要固定像素（如 1024×1820）时本机再缩放/裁切。
   - 实测速度：纯文字出图 28 秒；带参考图修改 54 秒。中文"冬季新品"四个字完全正确；改图保留了杯子和文字。PNG 约 1.8 MB。
   - 参考图可行：把图片作为回合输入，让工具用 `num_last_images_to_include`（Codex 上限 5 张，我们限 3 张）。
3. **公司中心延迟**：主机到 `dashboard-hk-api` 热连接每次约 0.1 秒，冷连接（含 TLS）约 1.1 秒。Ryn 对同一插件的中心请求是排队串行的（`peer_providers/service.py:_request` 的锁），一个页面加载几十个文件时逐个授权会卡几秒。
   - **设计确认**：按（调用方, 网页）缓存授权 60 秒；第一次打开多 0.1–1 秒，之后不再访问中心。
   - 顺带发现：测试时主机 Ryn 的公司通道本地接口 `workspace`、`catalog` 返回 503（原因没查），第 2 步接公司通道时先查清。
4. **点对点传输**：开发环境没装 Rust 原生传输，只测了 Python 备用通道：本机回环 10 MB 用 1.9 秒（5.2 MB/秒）。但它每发 8 个小包就等一次确认，真实网络延迟 30 毫秒时估计只有约 0.24 MB/秒，一张 1.8 MB 的图要约 8 秒。已安装的 Ryn 里带了原生 QUIC 传输（程序里有 `ryn_transport`），以前测过 35–46 MB/秒；同一局域网会先走直连 HTTP，更快。
   - **设计因此改为**：作品列表只传小缩略图（JPEG，约 100 KB），点开大图或下载时才传原图 PNG。

## 四、开发顺序（每步可单独验收）

1. **节点网页通道**：开放方入口、打开方网页端口、独立来源、票据、CSP、离线画面；两台节点开放一个测试页验证（含撤销、限流、冒充身份被拒）。
2. **接公司通道**：中心 `site.open` + 部署；公司目录显示开放的网页。
3. **本机出图接口 + 做图后台**：队列、存储、失败分类、记录。
4. **做图页面**：按界面稿实现同事的 3 个画面。
5. **我的做图服务页**。
6. **打包安装验收**：老板主机 + 一台同事电脑，真实出图、下载、离线、撤销。

## 不做（v1）

离线排队、跨节点 WebSocket、远程页面调用打开方的 Ryn 能力、多台电脑一起出图、额度限制（只显示用量）。
