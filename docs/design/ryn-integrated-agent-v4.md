# Ryn Agent 整体原型与源码参考核查（v4）

日期：2026-10-09。状态：设计与可点击原型，不代表 Agent 后端已经实现。本稿继承 [v3](ryn-model-pool-agent-v3.md) 的两条固定需求，替代其独立页面的呈现方案。

## 1. 固定产品语义

- 一个模型池：来源负责凭据、协议、地址；来源下有多个模型，每个模型独立设置能力、参数、默认用途和分享对象。
- 自己使用：当前 Ryn 节点拥有 Agent 会话、任务、上下文、记忆和工具执行权。模型可以来自本机、外部 API 或获授权的其他节点。
- 分享出去：提供方只处理本次推理请求及必要的鉴权、限流、协议转换，不加载提供方个人会话和工具。调用方自带本次需要的消息、工具 schema 等上下文；工具调用结果返回调用方执行。无状态不等于请求不能含历史，也不排除调用审计。
- 当前分享规则、Ryn 新任务默认模型、单任务模型覆盖三个配置互相独立。关闭分享不终止自己任务，修改默认模型不切换进行中的任务。
- 不把“配置成功”当成“可用 Agent”：协议适配器和实际模型必须正确支持工具调用往返，能力验证失败时在模型池中显示原因。

## 3. 核心原型路径

1. 首页 → 网盘 → 选中文件 → 让 Ryn 处理 → 侧边助手 → 开始任务 → 展开工作台 → 执行记录 → 结果文件 → 在网盘定位。
2. 服务 → 模型池 → 添加来源 → 发现或填写模型 → 能力检测 → 设为 Ryn 默认 → 工作台新任务使用该模型。
3. 同一模型行 → 分享 → 选择节点 → 管理共享 → API 接入查看可用模型；本机默认模型保持不变。
4. 任务执行时离开工作台 → 任务中心查看 → 回原会话继续；产品应基于服务端持久化事件恢复。

原型覆盖首页、服务、模型池、工作台、网盘、任务、设备、共享、API 接入，以及来源配置、模型参数、模型分享、工具范围、结果文件和任务详情弹层。外围探索/消息/设置等保留导航位置，用关联入口占位，未重画全部已有产品功能。

原型只运行一个示例任务，进度、能力检测和模型发现均为模拟，不访问真实文件、不调用真实模型。需要后端支持的恢复能力在标注中说明，不能将浏览器里的本地状态当成后端持久化已完成。

## 5. 具体借鉴方式

| 读到的设计 | Ryn 中的应用 | UI 表现 |
| --- | --- | --- |
| 会话对象跨轮持有状态 | Session / Task / Turn 分层，模型请求仅是其中一步 | 继续任务、回到原会话 |
| 工具结果回填主循环 | 模型提出调用 → Ryn 校验并执行 → 结果回填 → 再判断完成 | 展示实际操作、错误和验证结果 |
| 系统提示词分层组合 | 固定身份与原则、当前资源上下文、业务技能、工具定义分开 | 显示资源范围，避免把整套系统信息塞给模型 |
| 压缩而不是直接丢历史 | 保存目标、用户纠正、已完成步骤、资源 ID、待办与失败原因 | 长任务可以恢复，不必重新描述 |
| 中断和失败有明确状态 | 取消信号、工具幂等键、超时、有限重试、待确认状态 | 暂停/继续、失败原因、恢复入口 |

这些是我们对 Ryn 的设计转化，不是已完成实现。借鉴结构和行为；产品代码优先从许可清楚的开源组件和 Ryn 自有实现构建，不把泄露镜像直接并入工程，也不复制其大段提示词。

此前实际阅读的 ZCode 是官方 `zai-org/ZCode` 仓库，固定 SHA `29628c9acdb81b703bbd4080c207a0e7ce5e276e`，已读取 9 个核心/模型配置文件约 2744 行，另读 NOTICE/LICENSE；目录树统计不等于通读源码。参考范围包括运行器、上下文构建、工具调度、权限服务、压缩提示和来源模型配置组件。官方 [配置文档](https://zcode.z.ai/cn/docs/configuration) 支持本方案采用来源下多模型的交互结构。

## 6. 怎样接近“八成体验”

可以争取的是 Ryn 已支持业务范围内的成熟 Agent 体验：理解目标、连续调用工具、读取真实数据、写入结果、验证、失败后修正，以及跨页面继续。不能因为拿到源码或提示词就承诺通用能力达到 Claude Code/Codex 的 80%。模型能力、工具质量、上下文策略和运行器都影响结果。

建议先把验收分母固定为 30 个 Ryn 真实任务：文件查询与整理、模型配置与检测、共享规则查看与修改、设备诊断、失败恢复。保持相同模型与资源条件，人工确认每项结果正确、操作授权范围正确、无重复写入。24/30 成功才叫这个限定任务集达到 80%；它不等价于整个 Claude Code 产品能力的 80%。

推荐实施顺序：

1. 固定模型池实体与共享通道隔离，补适配器能力检测。
2. 建立单 Agent 主循环、持久化事件和少量高质量业务工具，先跑通完整文件任务。
3. 加入任务恢复、上下文压缩、错误纠正和变更预览，接入本稿的完整 UI 路径。
4. 跑任务集评测，根据失败样例改模型策略与工具；多 Agent、复杂技能发现后置。

本次没有修改上述运行时代码；交付为本设计和可点击整体原型。
