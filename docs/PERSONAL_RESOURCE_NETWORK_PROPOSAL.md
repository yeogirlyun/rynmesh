# Rynmesh：让家里的电脑成为个人云

> 将家中电脑的算力、桌面、文件及局域网服务，通过节点连接，提供给自己在任何地方使用的手机和电脑；随后扩展到好友之间的授权共享。

## 1. 为什么做

一个人通常拥有多台设备，但资源分散：家里的电脑性能强，外出的笔记本性能弱，文件又放在家中的 NAS 上。Rynmesh 将这些资源连接起来，让用户在当前设备上，直接使用另一台设备的能力。

**第一阶段以个人为中心：一个用户、两台设备就能获得价值，不依赖平台先拥有大量用户。** 节点互联和对外提供服务的方向继续保留，后续自然扩展到好友和更多节点。

## 2. 用户能做什么

| 场景 | 用户获得的能力 |
| --- | --- |
| 算力共享 | 在笔记本或手机上调用家中 RTX 5090 运行的模型、图像生成等服务，计算在家中完成。 |
| 远程桌面 | 在外使用手机或电脑，连接家中 Windows 桌面，操作已安装的软件。 |
| 文件共享 | 访问家中指定文件夹或 NAS，浏览、上传、下载文件，无需先搬到第三方云盘。 |
| 家庭服务访问 | 经家中节点访问指定的局域网 Web 应用、API 等服务。 |

统一使用路径：**打开 Rynmesh → 选择设备或资源 → 直接使用。** 每个节点支持自定义名称和备注；资源按授权范围展示。

## 3. 如何实现

连接关系：**手机 / 笔记本 / 公司电脑 → 授权连接 → 家中节点 → 本机资源或指定的家庭局域网服务。**

- **远程桌面：** 优先复用 Windows RDP，通过节点的受控通道连接家中电脑的 3389 服务，无需把该端口直接暴露到公网。先复用成熟的远程桌面客户端；手机端需要配套通道与客户端，或采用浏览器桌面网关，不能仅靠一个普通网页直接连接 RDP。[Microsoft RDP 说明](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-allow-access) · [浏览器网关参考](https://guacamole.apache.org/doc/gug/introduction.html)
- **文件与 NAS：** 先接入一个指定文件夹或现有 NAS 文件服务，提供统一文件入口，暂不自研完整网盘、同步和备份系统。NAS 无法安装节点时，由家中常在线的节点代理访问选定服务。这类局域网网关模式已有成熟实践。[子网网关参考](https://tailscale.com/docs/features/subnet-routers)
- **项目复用：** 延续当前项目，复用节点身份、发现、配对及已有 AI 服务能力；新增通用连接通道、资源授权、桌面与文件入口。已有远程管理页面不等于远程桌面，现有浏览器代理也不等于完整的家庭资源网关。

## 4. 分阶段推进

1. **先验证个人闭环：** 两台电脑配对，稳定调用家中 AI；接通 Windows 远程桌面和一个共享文件夹。
2. **再覆盖随身访问：** 完成手机使用路径，接入一种 NAS 服务，统一设备、资源和权限管理。
3. **最后扩展共享网络：** 将选定资源授权给好友或其他节点，保留撤销权限和访问记录。

首轮验收关注三件事：第一次连接是否容易、跨网络访问是否稳定、用户是否愿意反复使用。

## 5. 可行性与判断

**技术可行，值得在现有项目上聚焦验证。** 远程桌面、组网、NAS 访问各自已有成熟产品；我们的机会是把 AI、桌面、文件和 API 整合为一个容易配置和使用的个人资源入口，随后支持对外共享。

需要提前明确：家中服务设备必须开机联网；Windows 自带 RDP 主机需要 Pro、Enterprise、Education 或 Server，Home 版需另选方案。跨网直连失败时，需设计明确的失败提示或加密中继方案，并评估带宽成本，不能承诺所有网络都能直连。[Windows 版本要求](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-allow-access)

“任何节点都能访问”指**任何获得授权、网络条件允许的节点**，默认仅自己的设备使用；按资源开放，不默认开放整个家庭局域网。

**汇报表述：Rynmesh 先让一个人连通自己的设备，把家里的电脑变成随身可用的个人云；再让这些个人云之间按需共享服务。**
