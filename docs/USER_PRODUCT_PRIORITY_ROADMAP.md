## 1. 结论

下一阶段不应继续以 Transport、Provider、streaming 或桌面包格式作为产品主线。
这些工作有工程价值，但不能单独回答普通用户的核心问题：

> 我安装 Ryn 以后，今天能用它完成什么？明天为什么还会回来？

当前代码并非“功能太少”，而是已有能力分散在多个控制台页面，缺少从首次启动到
持续使用、再到两人分享的连贯用户旅程。因此建议把下一阶段调整为五个用户闭环：

```text
首次启动三分钟获得价值
  ↓
一键启用本地 AI
  ↓
统一 Ask Ryn 助手
  ↓
“我的内容”持续积累
  ↓
两台设备简单配对与分享
```

## 2. 产品判断依据

### 已有基础

- 默认公共来源和主动发现；
- For You、内容查看、收藏、历史、进度和反馈；
- 来源添加、网页监控、缓存和健康状态；
- Ollama 检测与选择，以及受管 GGUF 生命周期基础；
- Search & Ask、本地 Reader、Private AI 会话和 Provider 服务；
- 签名 Peer、发现、端到端加密消息和小附件；
- 发布、Manifest、内容获取和安全凭据。

### 主要产品断点

1. 首次引导介绍能力多，带用户完成真实任务少；
2. 本地 AI 仍需要用户安装外部软件并执行命令；
3. 多个 AI 入口概念重复、会话割裂；
4. 用户数据和内容能力存在，但没有统一“我的内容”；
5. Peer 能力存在，但现实中的两个用户没有简单安全的连接方式。

## 3. 五项需求的用户价值

| 顺序 | 需求 | 用户立即得到什么 | 复用的主要能力 | 不应同时做什么 |
|---|---|---|---|---|
| 1 | 首次启动三分钟获得价值 | 安装后马上看到、打开并反馈真实内容 | discovery、digest、reader、feedback | 模型、Peer、Credits 不作为前置 |
| 2 | 一键启用本地 AI | 不开终端即可得到第一次本地回答 | hardware、lifecycle、Ollama、ModelProvider | 不自动启用云端 |
| 3 | 统一 Ask Ryn | 一个入口完成普通问答、内容问答和历史会话 | ask、reader、Private AI、conversation store | 不开放自治写操作 |
| 4 | 我的内容 | 找回收藏、继续阅读、管理来源和文件 | consumption、sources、watchers、reader | 不做云同步和全盘索引 |
| 5 | 简单配对与分享 | 两人扫码连接并马上发消息/内容 | identity、discovery、messaging、manifest | 不把复杂服务权限塞入 v1 |

## 4. 阶段路线

### Phase A：个人用户首次价值

包含：首次成功 + 一键本地 AI。

完成定义：

- 新用户无需配置能完成第一个内容闭环；
- 需要 AI 时能在应用内完成安装并得到第一次回答；
- 任一 AI 故障不会破坏默认内容体验。

这是下一版本的首要发布门槛。

### Phase B：个人助手持续使用

包含：统一 Ask Ryn + 我的内容。

完成定义：

- AI 入口不再割裂；
- 用户能继续历史会话；
- 文章、网页和本地材料可以安全成为上下文；
- 保存、继续阅读、来源和文件形成长期可管理资产。

统一助手与“我的内容”的底层领域模型需要协调，但建议按顺序交付：先让助手有一个
真实会话，再逐步接入 Library 多选和文件。

### Phase C：两人网络价值

包含：简单配对与分享。

完成定义：

- 两个非技术用户安全完成配对；
- 能发送消息、小附件和内容卡片；
- 撤销本地立即生效；
- UI 不承诺未经验证的跨公网可达性。

Private AI friends-only、VPN、Agent 权限和复杂信用/结算均留到配对与分享稳定以后。

## 5. 与现有六个 Issue 的处理建议

### #28 Transport POST

保留为底层安全债和未来远端 Provider/Friend Mesh 的前置条件，但不作为用户版本的
宣传功能。仅在统一助手接入远端 Provider 或好友权限前完成。

### #24 Provider/模型切换

并入统一 Ask Ryn 的“计算位置与 Provider”切片，不单独建设另一个 Private AI
页面。先完成本地 AI 默认路径，再做高级切换。

### #25 Ask about this item

扩大并合入统一 Ask Ryn 的“内容上下文”切片。文章是一种上下文，架构需兼容后续
网页、PDF、本地文件和 Library 多选，而不是形成孤立按钮。

### #23 Private AI 流式输出

降级为体验增强。先保证真实会话、取消、重试、历史和内容问答完整；非流式闭环
稳定后再接入流式协议。

### #20 Linux 桌面包

作为发行覆盖并行推进，不应占用个人产品闭环的主线容量。只有明确存在 Linux
目标用户和真实桌面验收环境时再作为发布门槛。

### #30 Friend Mesh

拆成两个阶段：

1. 简单配对、消息、小附件、内容卡片、撤销；
2. Private AI friends-only、复杂权限、服务 ACL 和跨网络能力。

第一阶段仍必须遵守一次性邀请、关系凭证和撤销安全原则，不能用共享全局密钥换取
开发速度。

## 6. 建议的页面收敛

目标不是立刻删除所有页面，而是让普通用户只看到任务入口：

| 当前页面/入口 | 建议去向 |
|---|---|
| Home | 改为今日内容、继续使用和待处理事项 |
| For You | 保留为推荐主 feed |
| Explore | 逐步演进/合并到“我的内容”的浏览视图 |
| Search & Ask | 合并到 Ask Ryn |
| Private AI Chat | 能力和历史迁移到 Ask Ryn |
| AI curator 侧栏 | 变成 Ask Ryn 当前会话的紧凑视图 |
| Publish | 保留为高级功能，首页不作为前三主操作 |
| Peers | 高级诊断；普通连接走“连接朋友” |
| Services | 保留为高级服务目录，不作为首次用户路径 |
| Chat | 作为人与人的好友消息，明确区别于 Ask Ryn |
| Settings | 保留配置和隐私管理，运行细节逐步收纳 |

## 7. 共享产品和技术原则

- Browser 始终通过本地 node 访问模型、Peer 和文件；
- 首次路径不得依赖 fixture 或硬编码演示结果；
- 技术错误映射为稳定、可恢复的用户状态；
- 所有下载、上下文、列表、附件、重试和后台任务有界；
- 本地文件、Prompt、输出、邀请秘密不进入 Registry 和普通日志；
- 默认不启用云端、不发布文件、不信任 Peer、不扩展权限；
- 所有重要状态可以在应用重启后恢复；
- 用户内容、历史和偏好可以导出和范围化擦除；
- 每个需求必须用真实用户旅程验收，不能只以单元测试或 CI 绿色关闭。

## 8. 版本建议

### Release 1：Ryn 第一次真正可用

- 首次启动三分钟闭环；
- 一键本地 AI；
- 首页和错误恢复初步收敛。

### Release 2：Ryn 成为日常助手

- 统一 Ask Ryn；
- 当前文章/网页问答；
- 会话历史；
- 我的内容：已保存与继续阅读。

### Release 3：个人知识与两人分享

- 我的内容：来源、监控、本地文件和多选问答；
- 简单好友配对；
- 消息、小附件和内容卡片；
- 本地立即撤销。

## 9. 总体验收指标

在不依赖集中行为追踪的前提下，可使用本地、匿名自愿上报或人工测试衡量：

- 冷启动到首批真实内容的时间；
- 冷启动到首次打开/保存/反馈的时间；
- 本地 AI 启用完成率和首个回答时间；
- 用户是否能正确找到并继续昨天的内容/会话；
- 内容问答是否提供可打开引用；
- 两节点从生成邀请到首次送达的时间；
- 每个关键失败是否提供用户可执行的恢复动作。

核心发布判断不是页面数量，而是下面五个问题能否回答“是”：

1. 新用户能马上获得一次真实价值吗？
2. 不开终端能启用本地 AI 吗？
3. 用户知道去哪里问 Ryn 吗？
4. 用户第二天能找回昨天的材料和对话吗？
5. 两个现实中的用户能安全连接并分享吗？
