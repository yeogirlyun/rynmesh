## 范围

"Ryn agent"在本方案里指这 380 个文件（约 19 万行），由脚本按代码引用关系生成，不是人工挑的：

- `rynmesh/agent_runtime/`、`rynmesh/llm_package/` 全部（187 个 Python 文件，另有浏览器控制的文档和脚本）
- agent 依赖的模块（存储、文件事务、传输、个人空间等）和调用 agent 的模块
- 原生电脑控制（`native/ryn_computer_use`）和 JS 运行时
- 桌面外壳（`webapp/src-tauri/src`，进程、更新、保持唤醒）

Codex 一侧：开源源码 2,019 个 agent 相关文件、约 6,600 条机制逐条判定；Codex 桌面版是闭源的，只有别人的逆向资料，44 条机制单列为 S15，每条都标"待核实"。

## 怎么保证没漏

1. **Codex 对照，逐条不抽样**：上一轮判定的 1,513 行"缺/弱/未确认"全部按当前代码重新核实，每行都要写出 Ryn 和 Codex 两边打开过的 `文件:行号`，脚本检查路径和行号是否真实存在（查出的编造路径都打回重做）。
2. **新范围逐文件读完**：上一轮没读过的 197 个文件从头读到尾，每批有覆盖台账，脚本核对。
3. **每行都有去向**：1,750 行待处理全部落到改动项或"不做（写理由）"。高、中影响的行不允许以"收益太低"不做；不做的只有"重复"和"需老板决定"两种。脚本核对每行恰好一个去向。
4. **每个文件都有去向**：380 个文件逐个标"属于哪些改动项"或"看过、不改、理由"。
5. **第一轮独立盲查**：另一批人不看方案，按文件读全部代码列"该改的地方"（664 条）。和方案一对，方案当时只覆盖约一半——Codex 对照看不到 Ryn 自己的缺陷。漏掉的 449 条已全部补进方案。
6. **第二轮盲查**：分组更细、按 11 项清单查（硬限制、错误处理、并发、持久化、安全、自动处理、提示词、界面、平台、比 Codex 差、死代码），共 1,437 条。补漏前方案对高影响已覆盖 85%。漏掉的 842 条已全部补进方案。
7. **第三轮场景走查**：换方法，按 10 个真实使用场景（两小时长任务、重启和更新、中途插话、子 agent、MCP 长调用、中文 Windows、浏览器、电脑控制、记忆技能、定时任务）从界面到后端走整条链路，只记高、中问题，共 90 条。上面的 97% / 93% 就是这一轮的匹配结果。
8. **抽样复核判错**：随机抽 255 行（包括上一轮没复核的"不适用""持平"）独立重判，88% 完全同意，3% 不同意，不同意的已改正。

## 需要老板定的事

**权限与产品边界**
1. "自动处理"下桌面访问开关关着时视为已开——已按"自动处理 = 完全权限"写进 S04-I24，不同意可改。
2. "自动处理"是否也把节点应用（简历、招聘、桌面）的私有数据放行给模型（S08，B02-13）。
3. 记忆默认"人工审阅候选"是否随"自动处理"自动通过（S09-I24）。
4. 是否允许 agent 在密码框里输入（S11，B04-11）。
5. 是否加"浏览器禁止站点"和"电脑控制禁止应用"黑名单（默认空）。
6. 任务中途是否允许自动换到别的模型（会改变数据去向，S01-I14）。
7. 子 agent 委派默认值：建议"明确要求才派"（S07-I6）。
8. 取消默认预算硬顶后，跑飞的任务只靠"无进展就停"和主人硬上限兜底，花费可能更高（S07-I18，需知道）。
9. 独立检查器是否开放只读 diff 工具（S10）。

**网络与安全**
10. 默认生成网络密钥，或默认只绑本机（影响局域网发现和老版本互通）。
11. 是否支持用主机名或动态域名加好友（要放开 DNS 重绑定防护）。
12. 严格 P2P 连不通时，是否允许端到端加密中继兜底；设备间传文件在对称 NAT 下是否回退中继。
13. 联网搜索是否允许打开主人配置的内网白名单（现为防 SSRF 一律拦）。
14. 国内搜索源会把查询词发给第三方，是否默认启用（S06-I14）。
15. 是否在公开域名托管 OAuth client metadata 文档（S08）。

**架构与范围**
16. 是否把 Agent 拆成独立进程或独立事件循环。
17. Codex CLI 是否改用原生动态工具，在 Codex 回合内直接执行 Ryn 工具（S01）。
18. 是否删除没接入的代码：QuickJS 运行时、`shared_epoch_model` 等约 1,600 行（S11-I7、I16）。
19. 是否做 macOS / Linux / ARM64 的电脑控制和浏览器后端（S11-I26 等）。
20. 生图是否支持 Codex 之外的来源（S11）。
21. 是否给公开支持视觉的模型系列预置"支持图片"（S01）。
22. `transit` 中转是接入桌面发送路径，还是保留为命令行实验工具（S13）。
23. 自动更新的备用下载源放在哪台机器（S02-I25）。
24. 开发版余额里赚到的部分能否转成可用余额（S01-I26）。
25. 是否做 Codex 桌面版那种多 agent 并行改代码（worktree，S15-I17 起）。
26. 随包的闭源浏览器运行库能否随开源仓库分发（需法务核对，S11-I23）。
